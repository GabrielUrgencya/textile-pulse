## Descrição

Redesenhar o **módulo Dashboard** (tela de gestão) com **grid responsivo**, **hierarquia visual** clara, **section headers**, e **loading/empty/error** em todos os cards — reutilizando os primitives da 8.39. Aplicar **motion polish** (card-enter com stagger, countUp) em ambas as dashboards. Consistência total com o design system (sem cor nova).

## Critérios de Aceitação

### A — Layout e hierarquia
- [ ] **AC1:** **Given** o Dashboard, **When** renderiza, **Then** usa **grid responsivo** (sem empilhamento arbitrário): **região superior** = 4 KPIs primários (cards SM); **central** = gráfico principal (8/12, area chart) + lateral (4/12, ranking rápido + alertas); **inferior** = dados secundários (3 col).
- [x] **AC2:** **Given** as seções, **When** exibidas, **Then** há **section headers** com divider + label de contexto, separando visualmente os blocos.
- [ ] **AC3:** **Given** a importância dos dados, **When** dimensionados, **Then** KPIs primários têm **peso visual** maior que secundários (tamanho/tipografia), não todos iguais.
- [x] **AC4:** **Given** breakpoints, **When** a largura muda, **Then** o grid colapsa de forma responsiva (desktop → tablet → mobile) sem quebrar.

### B — Estados e gráficos
- [ ] **AC5:** **Given** qualquer card, **When** carregando, **Then** mostra **skeleton shimmer**; **When** sem dados, **Then** **empty state** (ícone + copy + CTA se aplicável); **When** erro, **Then** **error state** com retry. (primitives 8.39)
- [ ] **AC6:** **Given** o gráfico de produção do dia, **When** renderiza, **Then** é **area chart** com gradiente (8.39), sem grid vertical, tooltip glass.

### C — Motion (ambas as dashboards)
- [x] **AC7:** **Given** a montagem dos cards, **When** entram, **Then** usam **card-enter com stagger 50ms**; valores numéricos usam **countUp**; tudo a 60fps (só transform/opacity) e respeitando `prefers-reduced-motion`.
- [x] **AC8 (sem CLS):** **Given** o Dashboard, **When** carrega, **Then** os skeletons reservam o espaço final (sem layout shift perceptível).

### Geral
- [x] **AC9:** **Given** os KPIs/cards já existentes (incl. `MyMetaCard` da 8.37, `GoalsRow`, ranking, alertas), **When** após o redesign, **Then** continuam funcionando (sem regressão). Consistência total com o design system (nenhuma cor nova). `lint`, `tsc` passam.

**OUT:**

## Notas Técnicas
- **Reaproveitar dados:** `useDashboardData` e o payload de `/api/dashboard/all` permanecem; é redesign de apresentação, não de dados.
- **Hierarquia:** definir os 4 KPIs primários (ex.: produção do dia, % meta, lotes ativos, taxa de defeito) com `KpiCard` destaque; secundários menores.
- **Section headers:** componente simples (label uppercase + divider) reutilizável.
- **Motion polish na TV:** garantir que a 8.40 e a 8.42 compartilham os helpers de motion (8.39) — consistência entre as duas telas.
- **Responsivo:** BentoGrid em modo responsivo (8.39) com colapso por breakpoint.
