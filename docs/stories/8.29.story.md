## Descrição

O cálculo de "hoje" usa **data UTC** (`new Date().toISOString().slice(0,10)`) no client (`getDateRange`) e no servidor (`kpis/route.ts`). Como São Paulo é **UTC−3**, o "dia" vira às **21h BRT** (e a janela 00:00–03:00 BRT ainda conta o dia anterior). Resultado: os pontos não zeram à meia-noite local.

## Critérios de Aceitação

- [x] **AC1:** **Given** o fuso do tenant (`settings.timezone`, default `America/Sao_Paulo`), **When** o dashboard calcula "hoje", **Then** usa a data **local** do tenant (via `Intl.DateTimeFormat('en-CA', { timeZone })`), não UTC.
- [x] **AC2:** **Given** a virada do dia (00:00 BRT), **When** o dashboard recarrega/atualiza, **Then** o card "Pontos de Meta" exibe **0** e recomeça a contagem do novo dia.
- [x] **AC3:** **Given** o endpoint `kpis`, **When** chamado sem `from/to`, **Then** o default de "hoje" também respeita o fuso do tenant; e o filtro de scans por `[from,to]` cobre o **dia local** corretamente (limites do dia local convertidos para o range de timestamps).
- [x] **AC4:** **Given** scans do dia anterior, **When** o novo dia começa, **Then** eles permanecem no histórico (semana/mês) mas **não** entram no "hoje".
- [x] **AC5:** `lint`, `tsc`, `build` passam.

## Escopo

**IN:**
- `src/components/dashboard/Dashboard.tsx` — `getDateRange` calcula datas no fuso do tenant (helper com `Intl`).
- `src/app/api/dashboard/kpis/route.ts` — default de `from/to` no fuso do tenant; garantir que o filtro de scans respeite o dia local.
- (se necessário) helper compartilhado de data por fuso.

**OUT:**
- Configuração de fuso por usuário (usa o do tenant).
- Mudança de schema.

## Notas Técnicas
- Padrão de "hoje no fuso" já usado em `src/app/api/production/daily-plan/route.ts` (`todayInTz`) e no card do Dashboard — reutilizar/centralizar.
- Atenção: o `kpis` filtra scans por intervalo; se compara apenas `date(scan_at)` em UTC, o dia local não fecha certo. Garantir consistência entre o range enviado pelo client (datas locais) e o filtro no servidor.
- O Dashboard já recomputa `getDateRange` a cada tick de `now` (setInterval 1s), então a virada será refletida assim que a data local mudar.
