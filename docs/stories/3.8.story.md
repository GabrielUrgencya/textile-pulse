## Descricao

Como gerente, preciso de uma tela interna para gerenciar faccoes (fabricantes terceirizados), visualizar envios, acompanhar devoluções e controlar qualidade, para ter visibilidade completa da producao terceirizada sem depender do portal externo das faccoes.

**Contexto:** A pagina `/factions` existe como placeholder. O schema ja tem modelos completos: `Faction` (nome, tipo, contato, preco, rating, avg_delivery_days), `FactionShipment` (envios com status, quantidades, datas), `FactionInvitation`, `FactionToken`. O portal EXTERNO das faccoes ja existe (`/api/faction/*` com 14 endpoints: auth, shipments, returns, defects, financial, notifications). Esta story cria a visao INTERNA do gestor sobre essas mesmas faccoes.

## Criterios de Aceitacao

- [ ] **AC1:** Tela `/factions` lista todas as faccoes do tenant: nome, tipo, contato, rating, status (ativa/inativa). Cards ou tabela
- [ ] **AC2:** KPI row: total de faccoes ativas, envios em andamento, pecas em producao externa, media de rating
- [ ] **AC3:** Detalhe de faccao: ao clicar, modal ou sub-pagina com dados completos + lista de envios recentes (FactionShipment)
- [ ] **AC4:** Filtros: por status (ativa/inativa), busca por nome
- [ ] **AC5:** Indicadores visuais: rating com estrelas ou barra, envios atrasados destacados em vermelho
- [ ] **AC6:** Build e typecheck passam: `tsc --noEmit` + `next build` sem erros

## Escopo

**IN:**
- Substituir placeholder por tela funcional
- API `GET /api/factions` para listar faccoes do tenant (visao interna)
- API `GET /api/factions/[id]` para detalhes + envios recentes
- Listagem com filtros e KPIs
- Detalhe de faccao com envios

**OUT:**
- Criacao/edicao de faccoes (story futura — CRUD completo)
- Criacao de envios (feito pelo fluxo de producao existente)
- Portal externo das faccoes (ja existe, NAO TOCAR)
- Relatorios financeiros de faccoes
- Gestao de tokens de faccao (no modulo Settings — Story 3.5)
- Convites para faccoes
