## Descricao

Como administrador do LISION, preciso de uma tela para gerenciar membros da equipe (listar, criar, editar, desativar, resetar PIN) para poder fazer onboarding de novos funcionarios, ajustar roles/setores, gerar PINs para operadores do chao de fabrica e desativar pessoas que sairam da empresa.

**Contexto:** A pagina `/team` existe como placeholder vazio. O schema `profiles` ja tem todos os campos necessarios (name, email, phone, role, sector, pinCode, isActive, deletedAt). A autenticacao usa Supabase Auth — criar membro = `auth.admin.createUser()` + `profiles.insert()`. Operadores usam PIN (4-6 digitos) em vez de email/senha. A UX define master-detail com Sheet lateral (480px) para criar/editar.

## Criterios de Aceitacao

- [x] **AC1 — Listagem:** Pagina `/team` exibe lista de membros usando DataTable (Story 3.9). Colunas: Avatar+Nome, Role (StatusBadge), Setor, Status (Ativo/Inativo), Acoes. Desktop: tabela. Mobile (< 768px): cards empilhados com nome, role badge, setor.
- [x] **AC2 — Filtros:** FilterBar (Story 3.9) com: SearchInput (busca por nome), RoleFilter (dropdown: Todos, Admin, Gerente, Coordenador, Operador), StatusFilter (toggle: Ativos / Inativos). Default: mostra apenas ativos.
- [x] **AC3 — Criar membro:** Botao "Novo Membro" no PageHeader abre Sheet lateral (480px, direito). Campos: Nome*, Email (obrigatorio se role != OPERADOR), Telefone, Role* (dropdown), Setor* (dropdown). Se role = OPERADOR: campo PIN (4-6 digitos) com botao "Gerar PIN aleatorio" (usa `crypto.getRandomValues`, NAO `Math.random()`). Validacao inline campo a campo (nao submit-only). Botao "Criar Membro".
- [x] **AC4 — Editar membro:** Clicar em "Editar" na linha abre Sheet com dados preenchidos. Mesmos campos que criar, exceto: email e readonly apos criacao. Botao "Salvar".
- [x] **AC5 — Desativar membro:** Botao "Desativar" abre ConfirmDialog (Story 3.9) variant destructive. Titulo: "Desativar {nome}?". Corpo: "Esta pessoa perdera acesso ao sistema imediatamente. Dados historicos serao preservados." Botoes: "Cancelar" | "Desativar". NAO permite desativar a si mesmo (botao hidden/disabled). API: `PATCH /api/team/members/[id]/deactivate` seta `deleted_at = now()` e `is_active = false`.
- [x] **AC6 — Reset PIN:** Botao "Reset PIN" abre Popover inline (nao modal). Mensagem: "Novo PIN sera gerado. Anote e entregue ao operador." Botao "Confirmar Reset". Apos confirmar: mostra novo PIN em destaque (font-mono, tamanho grande) por 30 segundos, depois esconde com mensagem "PIN oculto. Resete novamente se necessario." API: `PATCH /api/team/members/[id]/reset-pin` gera novo PIN com `crypto.getRandomValues()`.
- [x] **AC7 — APIs Team:** (a) `GET /api/team/members?search=&role=&active=true` retorna membros do tenant com filtros. Paginacao simples. (b) `POST /api/team/members` cria usuario via `supabase.auth.admin.createUser()` + insere no profiles. Aceita `{ name, email, phone, role, sector, pin? }`. (c) `PATCH /api/team/members/[id]` atualiza profile. Nao permite editar role de si mesmo. (d) `PATCH /api/team/members/[id]/deactivate` soft-delete. Nao permite desativar a si mesmo. (e) `PATCH /api/team/members/[id]/reset-pin` gera novo PIN e retorna. Todas requerem permissao `users:manage`. Todas usam `withAuth()`.
- [x] **AC8 — Mobile:** Sheet → full-screen sheet (bottom). Tabela → cards verticais. Acoes → menu dropdown (3 dots icon).
- [x] **AC9 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

## Riscos

| Risco | Impacto | Mitigacao |
|-------|---------|-----------|
| `supabase.auth.admin.createUser()` requer service_role key | Seguranca | Usar apenas no server-side (API route), nunca expor key ao client |
| Criar usuario sem email (operador) pode ter limitacoes no Supabase Auth | Blocker | Testar: Supabase permite criar user com metadata sem email? Se nao, usar email dummy `operador-{uuid}@lision.internal` |
| PIN gerado precisa ser entregue fisicamente ao operador | UX | Mostrar PIN na tela por 30 segundos com opcao de copiar, depois ocultar |
