## Descricao

Como faccao, preciso confirmar recebimento de lotes, informar previsao de devolucao, e responder a defeitos (confirmar ou contestar). As regras de negocio R1 (contestacao com prazo), R2 (notificacao tripla) e R3 (limite de reagendamentos) devem ser implementadas nestes endpoints.

## Criterios de Aceitacao

- [ ] **AC1:** `PATCH /api/faction/shipments/[id]/confirm` registra confirmacao de recebimento (faction_confirmed_at = now)
- [ ] **AC2:** `PATCH /api/faction/returns/[id]/estimate` permite informar previsao de devolucao (data futura obrigatoria)
- [ ] **AC3:** Endpoint estimate valida `reschedule_count < 2`, retorna 403 se limite atingido (R3)
- [ ] **AC4:** Primeiro reagendamento: notificacao WARNING para gerente (R3)
- [ ] **AC5:** Segundo reagendamento: notificacao CRITICAL + e-mail + lote entra em OVERDUE (R3)
- [ ] **AC6:** `PATCH /api/faction/defects/[id]/respond` aceita CONFIRMED ou CONTESTED com motivo obrigatorio para contestacao
- [ ] **AC7:** Ao contestar, dispara notificacao tripla: interna CRITICAL + e-mail via Resend (R2)
- [ ] **AC8:** Ao contestar, registra `faction_response_at` para inicio da contagem de 3 dias uteis (R1)
- [ ] **AC9:** `PATCH /api/faction/notifications/read` marca notificacoes como lidas (array de IDs)
- [ ] **AC10:** Todos os endpoints validam que o recurso pertence a faccao da sessao

## Notas Tecnicas

- **R1 — Contestacao:** O endpoint de respond registra `faction_response_at = now()`. O job de vencimento (Story 6.6) monitora esse timestamp. Aqui so registramos.
- **R2 — Notificacao tripla:** Usar `sendNotification()` com `channels: ['internal', 'email']`. WhatsApp sera adicionado na Story 6.10.
- **R3 — Reagendamentos:**
  - `reschedule_count = 0 → 1`: WARNING, notificacao interna apenas
  - `reschedule_count = 1 → 2`: CRITICAL, notificacao interna + email + status OVERDUE
  - `reschedule_count >= 2`: HTTP 403 `RESCHEDULE_LIMIT_REACHED`
- **Validacao de propriedade:** Sempre verificar que o shipment/defect pertence a `session.factionId`
- **OVERDUE status:** Atualizar `faction_shipments.status` para OVERDUE quando segundo reagendamento ocorre
- **Source:** `docs/architecture/FACTION-PORTAL-ARCHITECTURE.md` secoes 4 (R1, R2, R3), 5.3
