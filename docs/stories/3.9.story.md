## Descricao

Como desenvolvedor do LISION, preciso de componentes e padroes fundamentais reutilizaveis (Error Boundary, hook padrao de data fetching, toast notifications, DataTable responsivo, skeleton loaders, permissoes atualizadas e DateRangeFilter) para que todos os modulos subsequentes (Settings, Team, Quality, Factions) possam ser construidos sobre uma base consistente e robusta.

**Contexto:** O gap analysis identificou que cada modulo novo precisa de: tabela responsiva (desktop → cards no mobile), estados de loading (skeletons), estados vazios, error handling padronizado, e filtros de data reutilizaveis. Construir isso ANTES dos modulos evita duplicacao e garante consistencia visual. A UX Architecture define specs detalhadas para cada componente em sua Secao 2.

## Criterios de Aceitacao

- [x] **AC1 — Error Boundary:** Componente `ErrorBoundary` que captura erros nao tratados em qualquer modulo, exibe fallback UI (icone + mensagem + botao "Tentar Novamente"), e loga o erro no console. Implementado como class component React (unico caso valido para class components). Fallback segue design system (LisionCard com mensagem centered).
- [x] **AC2 — useServerData hook:** Hook generico `useServerData<T>(url, options?)` que encapsula: fetch com AbortController, estados `data | isLoading | error`, tratamento de 401 (redirect to /login), tratamento de erro de rede (erro inline com retry), auto-refetch via `refetch()` retornado. Pattern identico ao descrito no gap analysis Secao 6.1.
- [x] **AC3 — Toast (Sonner):** Sonner ja esta instalado. Wiring necessario: (a) Componente `<Toaster />` adicionado no layout root `(app)/layout.tsx`, (b) helper `showToast(type, message)` que encapsula `toast.success()`, `toast.error()`, `toast.warning()` com defaults do design system (posicao bottom-right, duracao 4s success / 6s error). (c) Pelo menos 1 uso demonstravel (ex: erro de fetch mostra toast).
- [x] **AC4 — DataTable responsivo:** Componente `DataTable<T>` conforme spec UX (Secao 2.1): aceita `columns`, `data`, `loading`, `emptyState`, `onRowClick`, `mobileCard`. Em `>= md` renderiza tabela shadcn. Em `< md` renderiza `mobileCard()` como cards empilhados. Linhas com `hover:bg-secondary/30`. Suporte a sorting basico por coluna.
- [x] **AC5 — EmptyState:** Componente `EmptyState` conforme spec UX: icon (LucideIcon, size-12, opacity-30), title (15px), description (13px muted), action button opcional. Usado dentro de DataTable quando `data.length === 0`.
- [x] **AC6 — TableSkeleton:** Componente `TableSkeleton` com props `rows` (default 5) e `columns` (default 4). Desktop: skeleton rows com shimmer. Mobile (< md): 3 card skeletons empilhados. Usado dentro de DataTable quando `loading === true`.
- [x] **AC7 — ConfirmDialog:** Componente `ConfirmDialog` conforme spec UX: props `open`, `onConfirm`, `onCancel`, `title`, `description`, `consequences[]`, `confirmLabel`, `variant` (destructive | warning | default), `loading`. Baseado em AlertDialog (shadcn). Mobile: full-width buttons, sheet bottom.
- [x] **AC8 — Permissions update:** Arquivo `src/lib/permissions.ts` atualizado com as novas permissoes: `quality:view`, `quality:manage`, `factions:view`, `factions:manage`, `reports:export`. Permission matrix conforme gap analysis Secao 2.4 (ADMIN e GERENTE tem quality/factions, apenas ADMIN tem reports:export).
- [x] **AC9 — DateRangeFilter:** Componente `DateRangeFilter` conforme spec UX (Secao 2.1): aceita `value` (DateRange), `onChange`, `presets` (default: "Hoje", "7 dias", "30 dias", "Este mes"). Usa `Popover` + `Calendar` (shadcn). Desktop: inline com presets como ghost buttons. Mobile: full-width, presets empilhados. DateRange type: `{ from: Date, to: Date }`.
- [x] **AC10 — FilterBar wrapper:** Componente `FilterBar` conforme spec UX: wrapper `flex items-center gap-3 flex-wrap`. Mobile: stack vertical, cada filtro full-width. Usado como container padrao para filtros em todas as paginas.
- [x] **AC11 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

## Riscos

| Risco | Impacto | Mitigacao |
|-------|---------|-----------|
| Scope creep — 10 componentes e muito | Atraso | Cada componente e pequeno e independente. Priorizar AC1-AC6 como core, AC7-AC10 como complementar |
| DataTable generico pode ser over-engineered | Complexidade | Manter simples: tabela + cards mobile. Sem paginacao server-side (modulos adicionam depois) |
| DateRangeFilter depende de `date-fns` | Dependencia extra | `date-fns` ja esta no projeto (usado por shadcn Calendar) |
