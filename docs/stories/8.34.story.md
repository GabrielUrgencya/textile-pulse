## Descrição

A Tela de TV exibe tudo **unificado**, sem distinção por setor. O cliente quer um **toggle de seleção de setor** na própria TV: ao escolher um setor (= `Stage`: Corte, Costura, Embalagem, Conferência + demais do tenant), a TV passa a exibir **somente os dados daquele setor**. A seleção **persiste** (localStorage) e o **setor ativo fica sempre visível**. Sem telas separadas, sem múltiplos logins.

> Setor = `Stage`. A API `kiosk/dashboard` passa a aceitar `?stage_id=` (opcional). Sem `stage_id` → comportamento atual (visão geral), garantindo retrocompatibilidade.

## Critérios de Aceitação

### A — Seletor na TV
- [x] **AC1:** **Given** a Tela de TV, **When** exibida, **Then** há um **seletor de setor** em posição que não atrapalha o conteúdo principal (canto superior), listando os stages do tenant + a opção **"Visão Geral"** (sem filtro).
- [x] **AC2:** **Given** o seletor aberto, **When** lista os setores, **Then** mostra os stages ativos do tenant ordenados por `order_index` (Corte/Costura/Embalagem/Conferência + demais).
- [x] **AC3:** **Given** um setor selecionado, **When** confirmado, **Then** **todos** os dados da TV passam a refletir aquele setor (ver AC6); e o **nome do setor ativo** aparece como indicador visível na tela.
- [x] **AC4:** **Given** uma seleção feita, **When** a TV recarrega (refresh/reabertura), **Then** a seleção **persiste** (localStorage por token de kiosk) — não reseta para Visão Geral.
- [x] **AC5:** **Given** "Visão Geral" selecionada, **When** exibida, **Then** a TV mostra os dados consolidados de hoje (comportamento atual), sem regressão.

### B — API escopada por setor
- [x] **AC6:** **Given** `GET /api/kiosk/dashboard?token=...&stage_id=<uuid>`, **When** chamado, **Then** retorna os dados **escopados ao setor**: produção do setor (peças que deram **STAGE_IN** naquele stage hoje), pipeline/atividade/tempo filtrados ao stage; um campo identificando o setor ativo (`active_sector: { id, name }`).
- [x] **AC7:** **Given** `stage_id` ausente ou inválido, **When** chamado, **Then** cai na **visão geral** atual (sem erro), preservando o payload existente.
- [x] **AC8:** RLS/escopo de tenant respeitado (kiosk usa service_role + filtro por tenant do token); `stage_id` validado como pertencente ao tenant.

### Geral
- [x] **AC9:** `lint`, `tsc`, `build` passam. Polling atual (~10s) mantido.

## Notas Técnicas
- **Lista de stages:** a API já retorna `lots_by_stage`/`stages`; pode-se expor a lista de stages para o seletor no mesmo payload (ou usar o que já vem). Evitar chamada extra.
- **Produção do setor:** hoje a produção da TV conta peças que entram em **ESTOQUE** (8.19). Para um setor específico, contar **STAGE_IN no `stage_id`** (peças que passaram por aquele setor hoje), dedupe por lote, com coeficiente quando aplicável (paridade com `computeUserMeta`/kiosk).
- **Persistência:** `localStorage["tv_sector_<token>"]`; ler no mount, default = Visão Geral.
- **Retrocompatibilidade:** sem `stage_id`, payload idêntico ao atual.
