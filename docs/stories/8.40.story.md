## Descrição

Redesenhar a **Tela de TV** para um layout **bento grid** que **renderiza widgets a partir da config do setor** (8.38). Cada widget mapeia uma métrica do `computeSectorKpis` (8.35). Header redesenhado (nome do setor grande, toggle por **pill buttons**, relógio, data, status de conexão). Glassmorphism, thresholds visuais, countUp, motion stagger. A TV **assina** o canal Realtime **broadcast** `tv-config:{tenant}` e recarrega a config em **<2s** quando o admin publica — sem refresh.

> A TV nunca scrolla (`overflow: hidden`), nunca causa layout shift (CLS 0). Sem config → **layout default** (8.38). Reaproveita a lógica de KPIs por setor já existente (sector-kpis.ts).

## Critérios de Aceitação

### A — Layout bento + widgets
- [x] **AC1:** **Given** a TV com um setor ativo, **When** renderiza, **Then** usa **bento grid 12-col** (8.39) e exibe os widgets definidos na config do setor (8.38), cada um no seu `size`/`position`. Nenhum card empilhado.
- [x] **AC2:** **Given** os tipos de widget, **When** renderizados, **Then** há suporte a: `counter` (valor + delta vs ontem), `progress` (meta do momento + barra/circular), `chart` (produção por hora — area/sparkline), `ranking` (top colaboradores do setor), `timer` (tempo de processo do dia), `status` (semáforo facção / distância da meta), `comparison` (diária/semanal/mensal). Cada um mapeia uma `metric` do `sector_kpis`.
- [x] **AC3:** **Given** uma `metric` sem dado, **When** renderiza, **Then** o widget mostra estado vazio gracioso (sem crash, sem layout quebrado).

### B — Hierarquia, thresholds e motion
- [x] **AC4:** **Given** os widgets, **When** exibidos, **Then** seguem a hierarquia tipográfica (8.39): KPI principal ≥48px, label ≥11px upper, texto mínimo ≥18px (leitura à distância).
- [x] **AC5:** **Given** `thresholds` (warning/critical em % da meta), **When** o valor cruza, **Then** o widget aplica cor **semântica** (`--warning`/`--destructive`) — sem cor nova.
- [x] **AC6:** **Given** valores numéricos, **When** mudam no polling, **Then** animam com **countUp** (nunca piscam); cards entram com **stagger** no primeiro load.
- [x] **AC7 (CLS/perf):** **Given** a TV, **When** carrega/atualiza, **Then** **não** há layout shift (CLS 0) e as animações usam só `transform`/`opacity` (60fps).

### C — Header
- [x] **AC8:** **Given** o header, **When** exibido, **Then** mostra: **nome do setor** (tipografia grande), **toggle de setor por pill buttons** (não dropdown), **relógio HH:MM** monospace, **data**, e **status de conexão** (dot animado verde/vermelho).
- [x] **AC9:** **Given** a troca de setor pelos pills, **When** seleciona, **Then** os dados/widgets passam a refletir o setor; a seleção **persiste** (localStorage por token) — preserva o comportamento da 8.34.

### D — Tempo real (broadcast)
- [x] **AC10:** **Given** a TV aberta, **When** monta, **Then** **assina** o canal Realtime broadcast `tv-config:{tenantId}` (reusa padrão de `src/lib/realtime.ts`).

- [x] **AC12:** **Given** queda de conexão, **When** o Realtime cai, **Then** **reconecta automaticamente** e o dot de status reflete o estado; o polling de dados (~15s) continua como fallback.

## Notas Técnicas
- **Config na TV:** kiosk usa service_role; incluir o `layout` resolvido (salvo|default) no payload do `/api/kiosk/dashboard?stage_id=` evita uma 2ª chamada e mantém 1 request/poll.
- **Broadcast:** `supabase.channel('tv-config:'+tenantId).on('broadcast', { event: 'publish' }, cb).subscribe()`. A TV usa o cliente anon (broadcast não exige RLS). Ao receber, refaz o fetch da config/payload.
- **WidgetRenderer:** mapa `type → componente`; cada widget recebe `{ widget, kpis }` e extrai sua `metric`. Tipos desconhecidos → ignora com aviso (forward-compat).
- **CLS 0:** o grid e os tamanhos vêm da config no 1º render; usar skeleton com mesmas dimensões enquanto carrega.
- **Pill toggle:** reaproveitar os `sectors` já retornados pelo kiosk (8.34); só muda a apresentação (dropdown → pills).
