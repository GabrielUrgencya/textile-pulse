## Descrição

Interface **admin-only** para configurar **quais KPIs aparecem na TV de cada setor**, com **drag-and-drop** (@dnd-kit, já instalado). Sidebar de setores à esquerda, **preview** central em grid arrastável, **biblioteca de widgets** à direita. O admin arrasta widgets para o grid, redimensiona, edita label/threshold/metric, e **Salva + Publica** — o que persiste a config (8.38) e dispara o **broadcast** `tv-config:{tenant}`, atualizando a TV em **<2s**.

## Critérios de Aceitação

### A — Acesso e estrutura
- [x] **AC1:** **Given** a rota do builder (ex.: `/sector-dashboard` ou em Configurações), **When** um **ADMIN** acessa, **Then** vê: **sidebar de setores** (esquerda), **preview** (centro), **biblioteca de widgets** (direita).
- [x] **AC2:** **Given** um **não-Admin**, **When** tenta acessar a rota ou o item no menu, **Then** **não vê** e **não acessa** (guard + sidebar item adminOnly), e o `PUT` da API já é 403 (8.38).
- [x] **AC3:** **Given** a sidebar, **When** seleciona um setor, **Then** o preview carrega a config atual daquele setor (salva ou default, via GET 8.38).

### B — Edição drag-and-drop
- [x] **AC4:** **Given** a biblioteca de widgets, **When** o admin arrasta um widget para o grid do preview, **Then** o widget é **adicionado** na posição solta (@dnd-kit). Biblioteca: Meta do Momento, Distância da Meta, Tempo de Processo, Produção por Hora, Ranking de Colaboradores, Status de Prazo da Facção, Lotes Bipados, Taxa de Conclusão.
- [x] **AC5:** **Given** um widget no grid, **When** o admin o arrasta, **Then** **reposiciona**; **When** usa o controle de tamanho, **Then** redimensiona entre `sm/md/lg/xl`.
- [x] **AC6:** **Given** um widget selecionado, **When** edita, **Then** pode alterar **label** (texto livre), **metric** (mapeamento) e **thresholds** (warning/critical %); **When** remove, **Then** o widget sai do grid.
- [x] **AC7:** **Given** o preview, **When** renderiza os widgets, **Then** usa os **mesmos primitives** (8.39) e o **mesmo renderer** (8.40) da TV — fidelidade "what you see is what you get".

### C — Salvar e publicar
- [x] **AC8:** **Given** alterações no preview, **When** clica **"Salvar e publicar"**, **Then** chama `PUT /api/sector-dashboard-config` (8.38) e, em seguida, dispara o **broadcast** `tv-config:{tenantId}` (evento `publish`).
- [x] **AC9:** **Given** a publicação, **When** uma TV exibe aquele setor, **Then** atualiza em **<2s** sem refresh (consome a subscription da 8.40).
- [x] **AC10:** **Given** o botão **"Preview"**, **When** clicado, **Then** mostra como ficará (ex.: em tamanho TV) **antes** de publicar; alterações não-salvas não afetam a TV.
- [x] **AC11:** **Given** uma config salva, **When** recarrega o builder, **Then** o layout persistido é carregado corretamente.

### Geral
- [x] **AC12:** `lint`, `tsc` passam. Sem dependência nova (usar `@dnd-kit` já instalado).

## Notas Técnicas
- **@dnd-kit:** usar `@dnd-kit/core` + `@dnd-kit/sortable` (instalados). Grid de drop com snapping a colunas; persistir `position {x,y}` e `size`.
- **Publish:** após `PUT` bem-sucedido, `supabase.channel('tv-config:'+tenantId).send({ type:'broadcast', event:'publish', payload:{ stage_id } })`. (A TV refaz o fetch ao receber.)
- **WYSIWYG:** o preview deve usar o mesmo `WidgetRenderer` da TV com dados reais (ou mock do setor) para fidelidade.
- **Admin gate:** guard de página por `useUserProfile().role === 'ADMIN'` + item de menu adminOnly (padrão 8.33/Ranking) + PUT 403 no servidor (8.38).
- **UX de tamanho:** botões sm/md/lg/xl no inspector (drag-resize é opcional; priorizar seletor discreto para confiabilidade).
