## Descricao

Como admin da Liserie, preciso gerar tokens de acesso para faccoes (com PIN de 6 digitos), listar tokens existentes e revogar tokens comprometidos, para controlar o acesso das faccoes ao portal.

## Criterios de Aceitacao

- [ ] **AC1:** `POST /api/admin/faction-tokens` gera token UUID + PIN hash (bcrypt), retorna token UUID + PIN em texto claro (unica vez)
- [ ] **AC2:** Request body inclui `faction_id` e `name` (nome descritivo do token)
- [ ] **AC3:** PIN gerado automaticamente (6 digitos aleatorios) e retornado na response (unica exposicao)
- [ ] **AC4:** `GET /api/admin/faction-tokens` lista tokens do tenant (sem expor pin_hash)
- [ ] **AC5:** `DELETE /api/admin/faction-tokens/[id]` revoga token (is_active = false, soft delete)
- [ ] **AC6:** Somente usuarios com role ADMIN ou GERENTE podem acessar estes endpoints
- [ ] **AC7:** Response do POST inclui URL formatada: `liserie.lision.app/portal?token=<uuid>`

## Escopo

**IN:**
- 3 endpoints admin para CRUD de faction tokens
- Geracao segura de PIN (6 digitos)

- Formatacao de URL de acesso

**OUT:**

## Notas Tecnicas

- **PIN seguro:** `Math.floor(100000 + Math.random() * 900000).toString()` — garante 6 digitos
- **bcrypt:** `bcrypt.hash(pin, 10)` para gerar pin_hash
- **PIN exposto uma unica vez:** O POST retorna o PIN em texto claro. Apos isso, nao ha como recuperar. Admin deve anotar/enviar imediatamente.
- **Soft delete:** DELETE nao remove o registro, apenas marca `is_active = false`. Token inativo e rejeitado no login.
- **URL formatada:** `https://liserie.lision.app/portal?token=${token.token}` — admin copia e envia por WhatsApp
- **Auth:** Usar middleware de auth existente, verificar `session.role IN ('ADMIN', 'GERENTE')`
- **Source:** `docs/architecture/FACTION-PORTAL-ARCHITECTURE.md` secao 5.4
