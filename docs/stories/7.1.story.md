## Descricao

Como operador no chao de fabrica, preciso que a tela da TV exiba dados de producao com proposito claro (meta do dia, gargalos, alertas, ranking de faccoes), para que eu saiba instantaneamente se estamos no ritmo, onde esta travando e como esta a qualidade. A API atual retorna dados genericos — esta story reescreve `GET /api/kiosk/dashboard` para retornar todos os dados necessarios ao novo Andon Board.

## Notas Tecnicas

- **Score composto das faccoes:** `(pontualidade * 0.4) + (qualidade * 0.35) + (volume * 0.25)`
  - Pontualidade: `(entregas_no_prazo / total_entregas) * 100` — baseado em `faction_shipments`
  - Qualidade: `100 - (defeitos / pecas_recebidas * 100)` — baseado em `defect_records`
  - Volume: `(pecas_entregues / meta) * 100` — baseado em `faction_shipments`
  - Periodo: ultimos 30 dias
- **Current rate:** COUNT de scan_events na ultima hora, agrupado por hora
- **Peak rate:** MAX(scans por hora) do dia atual — agrupar scan_events por hora, pegar o maximo
- **Projected end:** `(produced_today / horas_decorridas) * horas_totais_turno` — calculado no backend usando shift start/end
- **Alertas stale lots:** Lotes cuja ultima bipagem foi ha mais de N horas. Usar `scan_events` com MAX(scanned_at) por lote, filtrar por threshold
- **Alertas shipments:** `faction_shipments` com `expected_return_at < now()` e `status != 'RETURNED'`
- **Manter:** Token auth existente via `validateKioskToken()` e `createServiceClient()`
