## Descricao

Como gerente do LISION, preciso de uma pagina de analytics de qualidade com KPIs, grafico Pareto de tipos de defeito, grafico de tendencia temporal e heatmap por etapa, para identificar onde e quando os defeitos ocorrem na producao e tomar acoes corretivas baseadas em dados.

**Contexto:** A pagina `/quality` existe como placeholder vazio. A tabela `defect_records` ja contem todos os dados necessarios (tipo, severidade, etapa, OP, faccao, timestamp). Nao ha nenhuma API de quality analytics — todas as 6 devem ser criadas. A UX define single-page com scroll vertical (sem tabs) e DateRangeFilter global. Charts usam Recharts (ja instalado no projeto).

## Criterios de Aceitacao

- [x] **AC1 — Layout pagina:** Pagina `/quality` com PageHeader (eyebrow="Qualidade", title="Analise de Defeitos"), DateRangeFilter no canto direito do header (presets: Hoje, 7 dias, 30 dias, Este mes). Layout: single-page scroll vertical com 5 secoes. DateRangeFilter controla TODOS os dados da pagina via hook unico `useQualityData(dateRange)`.
- [x] **AC2 — KPI Row (Secao 1):** 4 MetricBox: (1) Total Defeitos (numero + trend arrow), (2) Taxa de Defeito (% = defeitos/bipagens * 100 + trend), (3) Defeitos Criticos (contagem severity=CRITICAL), (4) Taxa de Resolucao (% resolvidos/total + trend). Trend: comparacao com periodo anterior de mesmo tamanho.
- [x] **AC3 — Pareto Chart (Secao 2):** Bar chart horizontal, top 8 tipos de defeito, sorted descrescente. Cada barra clicavel — expande detalhes inline (accordion) com: contagem, % do total, etapas mais afetadas. Dados: `GET /api/quality/by-type`. Chart: Recharts BarChart horizontal.
- [x] **AC4 — Trend Chart (Secao 3):** Area chart mostrando evolucao de defeitos ao longo do tempo. Periodo definido pelo DateRangeFilter. Hover tooltip com valor exato + data. Dados: `GET /api/quality/trend`. Chart: Recharts AreaChart.
- [x] **AC5 — Heatmap (Secao 4):** Grid onde eixo Y = etapas de producao, eixo X = tipos de defeito. Intensidade representada por opacity do `--destructive` color. Hover mostra contagem exata em tooltip. Dados: `GET /api/quality/by-stage`. Implementacao: grid CSS com cells colorizadas (nao canvas).
- [x] **AC6 — Tabela Faccoes (Secao 5):** Visivel apenas se usuario tem permissao `factions:view`. Tabela: Faccao, Total Defeitos, Taxa Contestacao (%), Rating. Linha clicavel → navega para `/factions/[id]`. Dados: `GET /api/quality/by-faction`. Se sem permissao, secao nao renderiza.
- [x] **AC7 — APIs Quality (6 endpoints):** (a) `GET /api/quality/overview?from=&to=` — total defeitos, taxa, criticos, resolucao, trends. (b) `GET /api/quality/by-type?from=&to=` — agrupado por defect_type, com contagem e %. (c) `GET /api/quality/by-stage?from=&to=` — matrix etapa x tipo com contagens. (d) `GET /api/quality/by-op?from=&to=` — defeitos por OP. (e) `GET /api/quality/by-faction?from=&to=` — defeitos por faccao com rating e contestacao. (f) `GET /api/quality/trend?from=&to=&interval=day|week` — serie temporal. Todas usam `withAuth()`, requerem `quality:view`.
- [x] **AC8 — Loading states:** Ao mudar DateRangeFilter: KPIs mostram skeleton (MetricBox shimmer), charts ficam com opacity-60 durante refetch. Skeleton shapes conforme contexto (barras para Pareto, area para Trend, grid para Heatmap).
- [x] **AC9 — Mobile (< 768px):** KPIs: grid 2x2. Charts: full-width, height reduzida (200px → 160px). Heatmap: scroll horizontal com indicador visual de scroll. Tabela faccoes: cards empilhados.

### SQL Exemplos para APIs

```sql
-- /api/quality/overview
SELECT
  COUNT(*) as total_defects,
  COUNT(*) FILTER (WHERE severity = 'CRITICAL') as critical_count,
  COUNT(*) FILTER (WHERE status = 'RESOLVED') as resolved_count,
  ROUND(COUNT(*) FILTER (WHERE status = 'RESOLVED')::decimal / NULLIF(COUNT(*), 0) * 100, 1) as resolution_rate
FROM defect_records
WHERE tenant_id = $1 AND created_at BETWEEN $2 AND $3;

-- /api/quality/by-type (Pareto)
SELECT defect_type, COUNT(*) as count,
  ROUND(COUNT(*)::decimal / SUM(COUNT(*)) OVER () * 100, 1) as percentage
FROM defect_records
WHERE tenant_id = $1 AND created_at BETWEEN $2 AND $3
GROUP BY defect_type ORDER BY count DESC LIMIT 8;

-- /api/quality/by-stage (Heatmap)
SELECT s.name as stage_name, dr.defect_type, COUNT(*) as count
FROM defect_records dr JOIN stages s ON dr.stage_id = s.id
WHERE dr.tenant_id = $1 AND dr.created_at BETWEEN $2 AND $3
GROUP BY s.name, dr.defect_type;

-- /api/quality/trend
SELECT DATE_TRUNC($4, created_at) as period, COUNT(*) as count
FROM defect_records
WHERE tenant_id = $1 AND created_at BETWEEN $2 AND $3
GROUP BY period ORDER BY period;
```
