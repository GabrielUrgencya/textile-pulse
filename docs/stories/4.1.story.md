## Descrição

Como equipe (Gabriel + Fabinho), precisamos validar o sistema completo com dados reais da Liserie e deixar em produção acessível, garantindo que o fluxo inteiro funciona de ponta a ponta no ambiente real da fábrica.

## Critérios de Aceitação

- [ ] **AC1:** Deploy em Vercel com domínio acessível (ex: `lision.vercel.app`)
- [ ] **AC2:** Supabase em produção com RLS (Row Level Security) ativado nas tabelas sensíveis
- [ ] **AC3:** Teste E2E completo: criar OP → gerar lotes → imprimir etiquetas → bipar em cada etapa → concluir OP
- [ ] **AC4:** Teste de retrabalho: bipar lote → reportar defeito → concluir retrabalho → continuar fluxo normal
- [ ] **AC5:** Teste em TV: dashboard Kiosk rodando na TV da fábrica da Liserie
- [ ] **AC6:** Teste com Fabinho: operador consegue fazer login por PIN e bipar lotes sem treinamento prévio
- [ ] **AC7:** Dados seed removidos, pelo menos 1 OP real da Liserie cadastrada e funcional

## Escopo

**IN:**
- Deploy Vercel com variáveis de ambiente de produção
- Configuração de RLS no Supabase
- Testes end-to-end manuais
- Validação com usuário real (Fabinho)
- Ajustes finos de UX encontrados nos testes
- Remoção de dados de teste

**OUT:**
- Testes automatizados E2E (Cypress/Playwright — Fase 2)
- Monitoramento/alertas de produção
- Backup automatizado
- Domínio customizado (usar .vercel.app na Fase 1)

## Notas Técnicas

- Vercel: conectar repo GitHub, configurar env vars (SUPABASE_URL, SUPABASE_ANON_KEY, etc.)
- RLS: políticas básicas — usuário só vê dados da própria organização (single-tenant na Fase 1, mas preparar para multi)
- Checklist de teste com Fabinho:
  1. Login por PIN no tablet
  2. Selecionar estação de bipagem
  3. Bipar 5 lotes em sequência
  4. Reportar 1 defeito
  5. Verificar TV mostrando progresso
- Ajustes de UX: priorizar feedback do Fabinho (ele é o usuário real)
