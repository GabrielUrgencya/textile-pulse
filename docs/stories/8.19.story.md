## Descricao

Fecha 4 lacunas do feedback operacional, todas ancoradas no marco "entrada no estoque":

- **A. Conclusão automática da OP:** hoje, ao bipar um lote no Estoque, só o lote vira `IN_STOCK`; a OP fica `OPEN` para sempre. Decisão do dono: a OP conclui (`COMPLETED`) quando **TODOS os seus lotes** estão `IN_STOCK`.
- **B. Meta por PEÇA (não por bipagem):** a produção é contada por nº de bipagens (`quantity_scanned` nunca é preenchido = 1 por bipada). Decisão do dono: contar as **peças do lote (lots.quantity) quando o lote ENTRA NO ESTOQUE** (× coeficiente quando meta ponderada). Tempo por etapa já entregue na 8.18.
- **C. Ocultar OPs concluídas:** lista principal mostra só OPs ativas; aba/filtro "Concluídas" para vê-las.
- **D. Editar lote manual:** além de fracionar (8.15), permitir editar a quantidade/identificação de um lote em etapa inicial.

## Decisoes do dono (2026-06-15)

1. OP conclui quando **todos os lotes = IN_STOCK**.
2. Produção por peça = **soma de lots.quantity dos lotes que entraram no estoque** no período (× coef quando ponderado).
3. OPs concluídas: **ocultas por padrão + aba "Concluídas"**.

## Criterios de Aceitacao

**A — Conclusão automática:**
- [ ] **AC1:** Given um lote bipado em ESTOQUE (STAGE_IN), When todos os lotes da OP estão `IN_STOCK`, Then `production_orders.status = 'COMPLETED'`
- [ ] **AC2:** Given nem todos os lotes no estoque, When um lote entra no estoque, Then a OP permanece no status atual (não conclui)
- [ ] **AC3:** Given OP sem lotes, When avaliada, Then NÃO é marcada como concluída
- [ ] **AC4:** Conclusão é idempotente (re-bipar não quebra) e registrada (updated_at)

**B — Meta por peça (entrada no estoque):**
- [ ] **AC5:** `produced_today` (não-ponderado) = SUM(lots.quantity) dos lotes com STAGE_IN em ESTOQUE no período
- [ ] **AC6:** Com meta ponderada, `weighted_points` = SUM(lots.quantity × COALESCE(meta_coefficient,1.0)) dos lotes que entraram no estoque
- [ ] **AC7:** Um lote que passa por várias etapas conta apenas UMA vez (no estoque), não por etapa
- [ ] **AC8:** Aplicado também na TV (`/api/kiosk/dashboard`), com isolamento por tenant
- [ ] **AC9:** Backward-compatible: sem entradas no estoque no dia → produção 0 (não conta bipagens de etapas intermediárias)

**C — Ocultar concluídas:**
- [ ] **AC10:** `GET /api/production/orders` oculta `COMPLETED` por padrão (além de `CANCELLED`)
- [ ] **AC11:** `GET /api/production/orders?status=COMPLETED` retorna as concluídas (para a aba)
- [ ] **AC12:** Lista de OPs ganha abas/filtro: "Ativas" (default) e "Concluídas"

**D — Editar lote:**
- [ ] **AC13:** `PATCH /api/production/lots/[id]` edita `quantity` (e identificação) de um lote em etapa inicial (CREATED/IN_CUT)
- [ ] **AC14:** Editar lote já avançado (além de IN_CUT) é bloqueado (409)
- [ ] **AC15:** UI de edição do lote no detalhe da OP (botão lápis)

**Geral:**
- [ ] **AC16:** `npm run lint`, `tsc --noEmit` e `npm run build` passam sem erros

## Notas Tecnicas

- **A (scan):** após setar lote IN_STOCK, contar lotes do `po_id` com status != IN_STOCK; se 0 e total>0 → `UPDATE production_orders SET status='COMPLETED'`. Apenas quando `stage.name === 'ESTOQUE'`.
- **B (peças):** identificar stage(s) ESTOQUE (por `name='ESTOQUE'`). Produção = join scan_events(event_type=STAGE_IN, stage=ESTOQUE, scanned_at∈range) → lots(quantity) → production_orders(meta_coefficient). Somar quantity (e quantity×coef). Substitui o uso de `quantity_scanned||1`.
  - Atenção `defect_rate`: manter denominador coerente (avaliar usar peças produzidas). Documentar a escolha.
- **C:** `.neq('status','CANCELLED').neq('status','COMPLETED')` por padrão; se `?status=X`, filtra por X. Abas no client chamam a API com/sem `status=COMPLETED`.
- **D:** validar `status IN ('CREATED','IN_CUT')`; permissão `orders:create`/`orders:edit`. Editar quantity de lote já no estoque corromperia a meta — por isso o bloqueio.
- **Status canônico da OP:** OPEN → (IN_PROGRESS opcional) → COMPLETED | CANCELLED. (Nota: KPI `active_ops` filtra `status='active'` — inconsistência pré-existente; alinhar para contar OPEN/IN_PROGRESS se for trivial.)
