## Descricao

Como equipe de operacoes, preciso de monitoramento de erros e performance configurado antes do go-live, para detectar e resolver problemas rapidamente no ambiente de producao.

## Criterios de Aceitacao

- [ ] **AC1:** `@sentry/nextjs` instalado e configurado para error tracking
- [ ] **AC2:** Sentry captura erros nao tratados em API Routes e client-side
- [ ] **AC3:** Sentry performance monitoring ativo (tracing de requests)
- [ ] **AC4:** Vercel Analytics habilitado para Web Vitals
- [ ] **AC5:** UptimeRobot configurado para monitorar endpoint de health check
- [ ] **AC6:** Endpoint `GET /api/health` retorna status do sistema (DB connection, version)
- [ ] **AC7:** Source maps enviados ao Sentry para stack traces legiveis
- [ ] **AC8:** Erros sensiveis (PIN, tokens) NAO sao enviados ao Sentry (scrubbing)

## Escopo

**IN:**
- Instalacao e configuracao do Sentry
- Vercel Analytics (incluso no Pro)
- UptimeRobot free tier
- Health check endpoint
- Data scrubbing para dados sensiveis

**OUT:**
- Axiom para logs estruturados (Fase 2)
- Alertas customizados (Fase 2)
- APM detalhado (Fase 2)
- Dashboard de observabilidade customizado

## Notas Tecnicas

- **Item 18 (v2.1):** Stack de observabilidade definida:
  - Sentry (`@sentry/nextjs`): error tracking + performance
  - Vercel Analytics (incluso no Pro): Web Vitals
  - UptimeRobot (free tier): monitoramento de uptime
  - Axiom para logs estruturados: Fase 2
- **Sentry setup:** Usar `npx @sentry/wizard@latest -i nextjs` para setup guiado
- **Source maps:** Configurar `sentry.properties` e upload via Vercel build
- **Data scrubbing:** Configurar `beforeSend` para remover PIN, tokens, dados pessoais
- **Health check:** Verificar conexao com Supabase via query simples (`SELECT 1`)
- **Source:** `docs/architecture/ARCHITECTURE-REVIEW-v2.1.md` item 18
