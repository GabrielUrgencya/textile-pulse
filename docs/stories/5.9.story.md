## Descricao

Como equipe de operacoes, preciso de monitoramento de erros e performance configurado antes do go-live, para detectar e resolver problemas rapidamente no ambiente de producao.

## Criterios de Aceitacao

- [x] **AC1:** `@sentry/nextjs` instalado e configurado para error tracking
- [x] **AC2:** Sentry captura erros nao tratados em API Routes e client-side
- [x] **AC3:** Sentry performance monitoring ativo (tracing de requests)
- [x] **AC4:** Vercel Analytics habilitado para Web Vitals
- [x] **AC5:** UptimeRobot configurado para monitorar endpoint de health check
- [x] **AC6:** Endpoint `GET /api/health` retorna status do sistema (DB connection, version)
- [x] **AC7:** Source maps enviados ao Sentry para stack traces legiveis
- [x] **AC8:** Erros sensiveis (PIN, tokens) NAO sao enviados ao Sentry (scrubbing)

## Notas Tecnicas

- **Item 18 (v2.1):** Stack de observabilidade definida:
  - Sentry (`@sentry/nextjs`): error tracking + performance
  - Vercel Analytics (incluso no Pro): Web Vitals
  - UptimeRobot (free tier): monitoramento de uptime
  - Axiom para logs estruturados: Fase 2
- **Sentry setup:** Usar `npx @sentry/wizard@latest -i nextjs` para setup guiado
- **Source maps:** Configurar `sentry.properties` e upload via Vercel build
- **Data scrubbing:** Configurar `beforeSend` para remover PIN, tokens, dados pessoais
- **Health check:** Verificar conexao com Supabase via query simples (`SELECT 1`)
- **Source:** `docs/architecture/ARCHITECTURE-REVIEW-v2.1.md` item 18
