## Descricao

Como administrador do LISION, preciso de uma pagina de configuracoes completa com tabs verticais (Perfil, Empresa, Etapas de Producao, Metas, Tokens de Acesso) para poder gerenciar o sistema: editar meu perfil, configurar etapas de producao com drag-and-drop, definir metas diarias (usadas pelo dashboard), e gerenciar tokens de acesso de kiosks e faccoes.

**Contexto:** A pagina `/settings` existe como placeholder vazio. O schema ja tem tudo: `profiles` (perfil do usuario), `stages` (etapas com `order_index`), `tenants.settings` (JSONB para metas), `kiosk_tokens` e `faction_tokens` (ja tem APIs existentes). As APIs de token kiosk/faccao ja existem em `/api/admin/*`. Esta story cria: APIs novas para profile, stages e targets + pagina completa com 5 tabs. O module Settings desbloqueia o dashboard (metas dinamicas) e o modulo Team (que precisa da infra de profile).

## Criterios de Aceitacao

- [x] **AC1 — Layout Settings:** Pagina `/settings` com layout 2 colunas: NavTabs vertical esquerdo (240px) + Content area (flex-1). Tabs: Perfil, Empresa, Etapas de Producao, Metas, Tokens de Acesso. Icones Lucide (User, Building, Layers, Target, Key). Mobile (< 768px): tabs viram horizontal scrollable ou accordion.
- [x] **AC2 — Tab Perfil:** Exibe nome, telefone (editaveis), email (readonly, vem do Supabase Auth), role (readonly, StatusBadge). Botao "Salvar Alteracoes" chama `PATCH /api/profile`. Toast de sucesso/erro apos save.
- [x] **AC3 — API Profile:** `GET /api/profile` retorna perfil do usuario logado. `PATCH /api/profile` aceita `{ name, phone }` e atualiza o profile do usuario autenticado. Apenas o proprio usuario pode editar (self-only). Validacao: nome obrigatorio, telefone opcional.
- [x] **AC4 — Tab Empresa:** Exibe nome da empresa, timezone (dropdown, default America/Sao_Paulo). Botao "Salvar". Dados vem/vao para `GET/PATCH /api/settings/tenant`.
- [x] **AC5 — API Settings Tenant:** `GET /api/settings/tenant` retorna dados do tenant do usuario logado (nome, settings JSONB). `PATCH /api/settings/tenant` aceita `{ name, timezone }`. Requer permissao `settings:manage`.
- [x] **AC6 — Tab Etapas (StageManager):** Lista sortable com drag-and-drop (`@dnd-kit/sortable`). Cada item: drag handle + numero sequencial + nome editavel (inline) + cor picker + botao delete. Botao "+ Adicionar Etapa" inline no fim da lista. Ao reordenar: auto-save com debounce 1s via `PATCH /api/settings/stages/reorder`. Delete: ConfirmDialog (Story 3.9) com checagem — se etapa tem bipagens, bloqueia delete com mensagem "Esta etapa possui X bipagens. Nao pode ser removida."
- [x] **AC7 — APIs Stages:** `GET /api/settings/stages` retorna stages do tenant ordenadas por `order_index`. `POST /api/settings/stages` cria nova stage com `{ name, color }`. `PATCH /api/settings/stages/[id]` edita nome/cor. `PATCH /api/settings/stages/reorder` aceita `{ stages: [{ id, order_index }] }` (batch update). `DELETE /api/settings/stages/[id]` — verifica se tem scan_records associados, se sim retorna 409 Conflict com contagem. Todas requerem `settings:manage`.
- [x] **AC8 — Tab Metas (TargetsConfig):** Campos: meta diaria de pecas (input numerico), meta de produtividade (% input), tolerancia de defeitos (% input), horario do turno inicio (time picker), horario do turno fim (time picker). Botao "Salvar Metas". Info text: "Estas metas serao usadas no dashboard e no kiosk TV". Dados vem/vao para `GET/PATCH /api/settings/targets`.
- [x] **AC9 — API Targets:** `GET /api/settings/targets` retorna targets do `tenants.settings` JSONB (ou defaults). `PATCH /api/settings/targets` aceita `{ dailyPiecesTarget, productivityTarget, defectTolerance, shiftStart, shiftEnd }` e salva no campo `settings` JSONB do tenant. Requer `settings:manage`.
- [x] **AC10 — Tab Tokens (TokenManager):** Duas sub-secoes: Tokens Kiosk e Tokens Faccao. Cada sub-secao: tabela com Nome, Token (masked `****-XXXX`), Status (StatusBadge), Criado em, botao Revogar. Botao "+ Novo Token Kiosk" / "+ Novo Token Faccao" abre Dialog. Kiosk Dialog: input nome → gera token → mostra URL copiavel (TokenDisplay component da Story 3.9). Faccao Dialog: selecionar faccao → gera token + PIN → mostra para copiar. Revogar: ConfirmDialog "Token sera invalidado imediatamente". Usa APIs existentes: `GET/POST/DELETE /api/admin/kiosk-tokens`, `GET/POST/DELETE /api/admin/faction-tokens`.
- [x] **AC11 — Drag-and-drop visual:** Item arrastado ganha `shadow-glow` + `scale(1.02)` + `opacity(0.9)` no placeholder. Ao soltar: animacao de reorder (200ms) + toast "Ordem salva". Mobile: drag-and-drop com long-press (300ms hold).
- [x] **AC12 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

|-------|---------|-----------|

| JSONB settings sem schema definido | Dados inconsistentes | Definir shape TypeScript e validar server-side com Zod |
| APIs de token existentes podem ter formato diferente | Incompatibilidade | Ler o codigo existente antes de integrar |
