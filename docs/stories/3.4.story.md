## Descricao

Como gerente de producao, preciso que o dashboard exiba APENAS dados reais do sistema, sem dados mock/fictícios que induzem a decisoes erradas. A sidebar deve mostrar o nome do usuario logado, nao um nome hardcoded.

**Contexto:** A auditoria tecnica (`docs/architecture/AUDIT-2026-05-20.md`) identificou que o Dashboard (`Dashboard.tsx`, 1098 linhas) usa extensivamente dados mock do arquivo `data.ts` (116 linhas) como fallback. Varios cards mostram dados 100% ficticios sem nenhum backend real. A sidebar mostra "Jonatas Mendes" hardcoded em vez do usuario logado. A barra de pesquisa, icones de notificacao e settings sao elementos visuais sem funcionalidade.

### User Profile — Hook Compartilhado

Criar hook `useUserProfile` em `src/hooks/use-user-profile.ts`:

```typescript
// 1. Buscar user do Supabase auth session (supabase.auth.getUser())
// 2. Buscar profile da tabela profiles (select full_name, role, avatar_url where id = user.id)
// 3. Calcular iniciais: "Gabriel Santos" → "GS"
// 4. Retornar: { user, profile: { fullName, role, initials, avatarUrl }, isLoading }
```

**IMPORTANTE — RLS:** O client-side usa `supabase` anonimo (`src/lib/supabase.ts`). Para o hook funcionar, a tabela `profiles` DEVE ter RLS policy que permita `SELECT` quando `auth.uid() = id`. Verificar se essa policy existe. Se nao, o @dev deve criar via migration ou usar `supabase.auth.getUser()` para obter dados basicos e fazer a query server-side via uma API `/api/profile` (GET).

Usar este hook em:
- `AppSidebar.tsx` (substituir linhas 129-141)
- `Dashboard.tsx` TopBar (substituir linhas 144-146) e saudacao (~linha 992)
