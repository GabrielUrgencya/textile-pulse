## Descrição

Como gerente de produção, preciso ver em tempo real o status de todas as OPs e a progressão dos lotes por etapa, para tomar decisões rápidas e identificar gargalos na linha de produção.

## Critérios de Aceitação

- [ ] **AC1:** Cards de resumo no topo: OPs ativas, lotes em produção, lotes concluídos hoje, % conclusão do dia
- [ ] **AC2:** Tabela de OPs com barra de progresso visual (% de lotes concluídos por OP)
- [ ] **AC3:** Visão por etapa: quantos lotes em cada etapa (`corte`, `costura`, etc.) — gráfico de barras horizontal
- [ ] **AC4:** Atualização automática a cada 30s (polling) ou real-time via Supabase Realtime
- [ ] **AC5:** Filtros: período, status da OP, cliente
- [ ] **AC6:** Responsivo: funciona em desktop e tablet

## Escopo

**IN:**
- Página `/dashboard` protegida (admin + gerente)
- Cards KPI com métricas do dia
- Tabela de OPs com progresso visual
- Gráfico de barras por etapa de produção
- Auto-refresh via polling (30s)
- Filtros de período, status, cliente

**OUT:**
- Gráficos históricos (tendência semanal/mensal — Fase 2)
- Exportação de relatórios
- Alertas/notificações push
- Supabase Realtime (usar polling na Fase 1, real-time na Fase 2)

## Dependências

| Story | Motivo |
|-------|--------|
| 2.1 | OPs e sub-lotes precisam existir |
| 2.2 | Eventos de bipagem alimentam as métricas |

## Notas Técnicas

- Usar polling simples (setInterval 30s) na Fase 1 — Supabase Realtime fica para Fase 2
- Barras de progresso: CSS puro com `width: {percent}%`, sem biblioteca de gráficos pesada
- Gráfico de barras por etapa: pode ser HTML/CSS puro ou biblioteca leve (ex: `recharts`)
- Queries otimizadas: usar `GROUP BY` e `COUNT` no Prisma, não trazer todos os registros
- Cards KPI: consultas agregadas separadas para performance
