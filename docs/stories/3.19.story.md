## Descricao

Como usuario do LISION, preciso que os targets do dashboard sejam dinamicos (nao hardcoded), que componentes ausentes da spec UX sejam criados (TokenDisplay), que defeitos de NaN sejam corrigidos, e que pequenos polimentos de qualidade sejam aplicados (trends empty state, sw cache, localStorage resilience, date-fns centralizado) — para uma experiencia confiavel e alinhada com a arquitetura definida.

**Contexto:** A review de QA (docs/qa/QA_FIX_REQUEST.md) identificou issues de severidade MEDIUM e LOW que nao bloqueiam o merge mas devem ser corrigidos antes da producao. Incluem: dashboard targets hardcoded (magic numbers), FactionScoreCard NaN potencial, TokenDisplay nunca criado (spec UX 2.2), trends sem empty state, service worker cache stale, localStorage sem try/catch, e date-fns locale disperso.

## Criterios de Aceitacao

- [ ] **AC1 — Dashboard targets dinamicos (M2):** `GoalsRow` no Dashboard busca targets da configuracao do tenant (API `/api/settings/targets` ou campo na tabela de tenant). Se nao existir configuracao, usa valores atuais (100 lotes, 15 OPs) como fallback com indicacao visual de "meta padrao". Dado tenant com meta de 200 lotes/dia configurada, dashboard exibe target: 200.

- [ ] **AC2 — FactionScoreCard sem NaN (M3):** `FactionScoreCard` trata `rating` null/undefined com fallback: `Number(rating ?? 0)`. Se rating nao existe, exibe "Sem avaliacao" (texto) ao inves de NaN ou 0 estrelas. Dado faccao sem rating cadastrado, card mostra "Sem avaliacao" de forma graceful.

- [ ] **AC3 — TokenDisplay criado (UX2):** Componente `src/components/settings/TokenDisplay.tsx` criado conforme spec UX secao 2.2: (a) Exibicao masked do token (mostra apenas ultimos 4 chars: `••••••••abcd`), (b) Botao copiar com feedback (icone clipboard → checkmark por 2s), (c) Botao revogar com ConfirmDialog, (d) Indicador de expiracao (badge "Expira em X dias" ou "Expirado"). Integrado na pagina de settings/tokens existente.

- [ ] **AC4 — Trends empty state (L1):** `GET /api/quality/trends` retorna `{ data: [], hasData: false }` quando todos os pontos do periodo sao zero. Frontend exibe empty state "Nenhum dado no periodo" ao inves de grafico com linha flat zero. Se houver pelo menos 1 ponto > 0, renderiza grafico normalmente.

- [ ] **AC5 — Service worker cache versionado (L2):** `public/sw.js` usa cache name dinamico: `lision-portal-v{TIMESTAMP}` ou vinculado a versao do build. No evento `activate`, limpa caches antigos. Apos novo deploy, proxima visita ao portal atualiza o service worker.

- [ ] **AC6 — localStorage resiliente (L3):** `src/app/portal/install-prompt.tsx` envolve TODAS as chamadas `localStorage.getItem()` e `localStorage.setItem()` em try/catch. Em caso de erro (modo privado Safari, storage cheio), fallback silencioso: getItem retorna null, setItem e no-op. Componente nao lanca excecao em nenhuma circunstancia.

- [ ] **AC7 — date-fns locale centralizado (L4):** Criar `src/lib/date.ts` que exporta o locale pt-BR e funcoes formatadas pre-configuradas. Todos os imports de `date-fns/locale/pt-BR` dispersos pelo codebase sao substituidos por import de `@/lib/date`. Um unico ponto de importacao do locale.

- [ ] **AC8 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.
