## Descrição

Como gerente, preciso de uma tela simplificada para exibir em TV no chão de fábrica, mostrando o progresso da produção do dia com fontes grandes e alto contraste, sem necessidade de interação.

**Contexto:** A infraestrutura kiosk JÁ EXISTE: tabela `kiosk_tokens` no schema, middleware de validação de token (`kiosk-middleware.ts`), API `GET /api/kiosk/dashboard`, CRUD de tokens (`/api/admin/kiosk-tokens`), e uma página skeleton em `src/app/(kiosk)/tv/page.tsx`. O skeleton atual tem layout com inline styles, KPIs básicos (scans_today, active_ops, lots_by_stage), auto-refresh de 30s e dark mode fixo. Esta story EVOLUI o skeleton para um dashboard TV-first completo com progresso por OP, alertas de atraso, auto-scroll e design polido.

## Riscos

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Auto-scroll pode ser irritante em TVs com pouco conteúdo | UX ruim se scroll ativa com 2-3 OPs | Só ativar scroll se conteúdo excede viewport (detect via JS) |
| Query de lotes parados pode ser lenta com muitos lotes | Performance na TV | Limitar query a lotes com status ativo (não IN_STOCK, não CREATED) |
| Fontes grandes podem cortar textos em OPs com nomes longos | Layout quebrado | Truncar com ellipsis + tooltip (ou sem tooltip na TV) |

### API — Evolução do GET /api/kiosk/dashboard

**Arquivo:** `src/app/api/kiosk/dashboard/route.ts` (MODIFICAR)

O endpoint atual retorna `{ kiosk, kpis: { scans_today, active_ops, lots_by_stage }, timestamp }`.

Evoluir para retornar também:

```typescript
{
  kiosk: { token_name, scope },
  kpis: { scans_today, active_ops, lots_by_stage },
  // NOVO: OPs do dia com progresso por stage
  ops: [
    {
      id, op_number, product_name, total_quantity,
      lots_count, lots_by_stage: [{ stage_name, count }],
      progress_percent  // lotes em IN_STOCK ou IN_PACKING / total
    }
  ],
  // NOVO: Lotes parados > 2h
  stale_lots: [
    {
      barcode, lot_number, op_number,
      stage_name, hours_stalled,
      entered_current_stage_at
    }
  ],
  timestamp
}
```

**Query para lotes parados:**
```sql
-- Lotes com entered_current_stage_at < NOW() - 2h
-- Excluir status: CREATED, IN_STOCK, PARTIALLY_STOCKED
SELECT l.barcode, l.lot_number, l.entered_current_stage_at,
       s.display_name as stage_name,
       po.op_number
FROM lots l
JOIN stages s ON l.current_stage_id = s.id
JOIN production_orders po ON l.po_id = po.id
WHERE l.entered_current_stage_at < NOW() - INTERVAL '2 hours'
  AND l.status NOT IN ('CREATED', 'IN_STOCK', 'PARTIALLY_STOCKED')
```

### Auto-scroll

```css
@keyframes autoScroll {
  0%, 10% { transform: translateY(0); }
  45%, 55% { transform: translateY(calc(-100% + 100vh)); }
  90%, 100% { transform: translateY(0); }
}
```

Só aplicar se `scrollHeight > clientHeight`. Detectar via `ResizeObserver` ou `useEffect`.
