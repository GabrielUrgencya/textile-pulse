# Story 3.20 — API Error Handling Padronizado + Tenant Guard

## Status: Ready for Review

## Story

Como equipe de desenvolvimento, precisamos que TODAS as rotas API tenham logging consistente de erros do Supabase e validação de tenant_id obrigatória, para que erros em produção sejam diagnosticáveis e inserts não falhem silenciosamente por RLS quando tenant_id é null.

## Origin

- Auditoria @qa: 28 HIGH (erros engolidos) + 6 CRITICAL (missing tenant_id guards)
- Plano @architect: Helper functions `dbError()` e `requireTenantId()` em `src/lib/api-helpers.ts`

## Acceptance Criteria

### AC1: Helper functions criadas
- **Given** nenhum padrão centralizado de error handling existe
- **When** `src/lib/api-helpers.ts` é criado
- **Then** contém `dbError(route: string, error: PostgrestError): NextResponse` que faz `console.error("[route]", error.message, error.code, error.details)` e retorna `NextResponse.json({ error: error.message || "Database error" }, { status: 500 })`
- **And** contém `requireTenantId(user: User): { tenantId: string; error: null } | { tenantId: null; error: NextResponse }` que retorna 400 se tenant_id é null

### AC2: Erros engolidos corrigidos — 28 rotas
- **Given** 28 rotas têm `if (error) { return NextResponse.json({ error: "Failed to..." }, { status: 500 }); }` sem logging
- **When** cada rota é atualizada
- **Then** cada `if (error)` block é substituído por `if (error) return dbError("METHOD /api/path", error);`
- **And** o import de `dbError` de `@/lib/api-helpers` é adicionado

### AC3: Tenant guards aplicados — 6 rotas
- **Given** 6 rotas usam `user.app_metadata?.tenant_id` sem verificar null
- **When** cada rota é atualizada
- **Then** usa `const t = requireTenantId(user); if (t.error) return t.error;` antes de qualquer query/insert com tenant_id
- **And** substitui `tenantId` por `t.tenantId` no restante do handler

Rotas afetadas:
1. `src/app/api/shipments/route.ts` POST — insert em faction_shipments

## Dev Notes

### Padrão dbError — uso:
```typescript
import { dbError } from "@/lib/api-helpers";

// Substituir:
if (error) {
  return NextResponse.json({ error: "Failed to X" }, { status: 500 });
}

// Por:
if (error) return dbError("POST /api/shipments", error);
```

### Padrão requireTenantId — uso:
```typescript
import { requireTenantId } from "@/lib/api-helpers";

// Substituir:
const tenantId = user.app_metadata?.tenant_id;

// Por:
const t = requireTenantId(user);
if (t.error) return t.error;
// Usar t.tenantId daqui em diante
```
