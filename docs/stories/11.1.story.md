## Story

**Como** administrador do LISION Vendas,
**quero** que a tela de Equipe do Vendas mostre apenas pessoas do setor de Vendas (nunca a equipe de produção) e me permita criar consultoras ali mesmo,
**para que** os dados de equipe fiquem isolados do LISION de produção, como setores distintos que são.

## Contexto

Hoje `sales_admin_directory_v1` faz `FROM public.profiles WHERE tenant_id = v_tenant` e a tela `SalesAdminTeam` lista **toda a equipe de produção** para "habilitar". Isso vaza a equipe de produção para o Vendas. As vendas/metas já são isoladas (tabelas `sales_*`); só o diretório de pessoas vaza.

## Critérios de Aceite (Given/When/Then)

1. **Diretório escopado.**
   Dado um tenant com perfis de produção sem vínculo de Vendas,
   quando o admin abre a Equipe do Vendas,
   então a lista mostra **apenas** perfis com vínculo em `sales_memberships` (ativo ou inativo) **OU** com cargo `VENDEDOR` — nenhum perfil exclusivo de produção aparece.

2. **Nova consultora.**
   Dado o admin na Equipe do Vendas,
   quando usa "Nova consultora" e informa nome + e-mail (+ senha/PIN conforme o fluxo de `/api/team/members`),
   então é criado um usuário com cargo `VENDEDOR`, setor `Vendas`, com vínculo `sales_memberships` `CONSULTANT` ativo (via `sales-vendedor-link`), e ele passa a aparecer no diretório escopado.

3. **Adicionar administrador (porta explícita).**
   Dado o admin na Equipe do Vendas,
   quando usa "Adicionar administrador" e busca por nome/e-mail,
   então pode selecionar um perfil existente do tenant (única porta que consulta todos os profiles) e promovê-lo a `ADMIN` do Vendas (vínculo `sales_memberships` ADMIN ativo).

4. **Sem vazamento textual.**
   O texto "Habilite perfis que já pertencem a este tenant" é removido/substituído por copy coerente com o isolamento.

5. **Idempotência e segurança.**
   Todas as RPCs mantêm guarda `sales_is_admin` + escopo por tenant; a busca de admin é admin-only.

## Escopo

**IN:** reescrita da RPC `sales_admin_directory_v1` (scoped); nova RPC de busca de perfis para admin (`sales_admin_profile_search_v1`); UI de "Nova consultora" e "Adicionar administrador" em `SalesAdminTeam`; rota/endpoint para a busca.
**OUT:** separar consultora de `profiles`; mexer em métricas/fechamento; matriz de permissões (Story 11.4).

## Dev Notes

- **RPC scoped** (`prisma/migrations/…_sales_directory_scoped/migration.sql`, `CREATE OR REPLACE`):
  `... FROM public.profiles p LEFT JOIN public.sales_memberships sm ON ... WHERE p.tenant_id = v_tenant AND (sm.id IS NOT NULL OR p.role = 'VENDEDOR')`.
  Confirmar que a criação de VENDEDOR grava `profiles.role = 'VENDEDOR'` (rota `src/app/api/team/members/route.ts`); se gravar só em `app_metadata`, ajustar o predicado para also cobrir isso (ex.: incluir join com auth via uma view/coluna já existente) OU garantir `profiles.role`.
- **RPC de busca** `sales_admin_profile_search_v1(p_query text)`: admin-only; retorna perfis do tenant que casam o termo (nome/e-mail), com `membership_id`/`sales_role` para indicar quem já é do Vendas. Limite (ex.: 20).
- **UI** `src/components/sales/admin/SalesAdminTeam.tsx`: dois CTAs no topo — "Nova consultora" (reutiliza o fluxo de criação com `role: VENDEDOR`, `sector: VENDAS`, como em `MemberForm`/`/api/team/members`) e "Adicionar administrador" (dialog com busca → `sales_admin_profile_search_v1` → seleciona → `PUT /api/vendas/admin/memberships` role ADMIN).
- **Lib**: `sales-vendedor-link.ts` (já existe) garante o vínculo CONSULTANT ao criar VENDEDOR.
- Migrations idempotentes; aplicar com protocolo probe→aplicar→verificar e OK do usuário.
