## Descricao

Como gestor da fabrica, preciso de um endpoint que retorne os KPIs de producao em tempo real para alimentar o dashboard, incluindo producao total, taxas de defeito, status das OPs ativas, e top produtores — tudo computado via query, sem campos desnormalizados.

## Criterios de Aceitacao

- [ ] **AC1:** Endpoint `GET /api/dashboard/kpis` retorna KPIs agregados do tenant
- [ ] **AC2:** KPIs incluem: total produzido hoje, taxa de defeito, OPs ativas, lotes por estagio
- [ ] **AC3:** `top_producers` computado via query sobre `scan_events` (JSONB mantido para leitura — Item 14 v2.1)
- [ ] **AC4:** Endpoint `GET /api/dashboard/production-chart` retorna dados de grafico (producao por hora/dia)
- [ ] **AC5:** Todas as quantidades computadas via query (Opcao A — Item 5 v2.1)
- [ ] **AC6:** Filtro por periodo: `?from=YYYY-MM-DD&to=YYYY-MM-DD`
- [ ] **AC7:** Performance aceitavel (<500ms) para volume do piloto
- [ ] **AC8:** Canal Realtime qualificado por tenant: `production-updates:{tenantId}` (Item 7 v2.1)

## Notas Tecnicas

- **Item 5 (v2.1) — Opcao A:** TODAS as quantidades sao computadas via query. Exemplos:
  - Producao total: `COUNT(DISTINCT lot_id) FROM scan_events WHERE stage_id = finalStage AND DATE(scanned_at) = today`
  - Taxa defeito: `COUNT(defect_records) / COUNT(scan_events) * 100`
  - Lotes por estagio: `GROUP BY current_stage_id FROM lots WHERE po.status = 'active'`
- **Item 7 (v2.1):** Canal Realtime deve ser `supabase.channel('production-updates:{tenantId}')`. RLS filtra no Realtime.
- **Item 14 (v2.1):** `daily_metrics.top_producers` e `daily_metrics.faction_summary` mantem JSONB na Fase 1. Normalizar para `daily_producer_metrics` na Fase 2 antes de calculos de pagamento.
- **Performance:** Queries sobre <500 lotes/mes sao rapidas. Se necessario, criar indices em `scan_events(scanned_at, stage_id)`.
