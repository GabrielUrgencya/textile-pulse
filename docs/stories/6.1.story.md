## Descricao

Como admin da Liserie, preciso gerar links de acesso para faccoes externas, e como faccao, preciso acessar o portal usando token + PIN de 6 digitos, sem cadastro. O sistema deve autenticar via cookie HttpOnly e isolar dados por faccao.

## Criterios de Aceitacao

- [ ] **AC1:** Migration cria tabela `faction_tokens` com campos: id, tenant_id, faction_id, token (UUID unique), pin_hash, name, is_active, last_accessed_at, created_at
- [ ] **AC2:** RLS policy `faction_tokens_admin_only` restringe acesso a admins do tenant
- [ ] **AC3:** Indice `idx_faction_tokens_token` criado para lookup rapido de tokens ativos
- [ ] **AC4:** Modelo Prisma `FactionToken` criado com relations para `Tenant` e `Faction`
- [ ] **AC5:** `POST /api/faction/auth/login` valida token + PIN (bcrypt.compare), cria session cookie (HttpOnly, SameSite=Strict, Secure, max-age=30 dias)
- [ ] **AC6:** `POST /api/faction/auth/logout` destroi session cookie
- [ ] **AC7:** `faction-middleware.ts` criado, retorna `FactionSession { tenantId, factionId, tokenId, factionName }`
- [ ] **AC8:** Rate limiting: 5 tentativas / 15 min por IP + token
- [ ] **AC9:** Middleware principal atualizado: rotas `/api/faction/*` e `/portal` adicionadas como publicas

## Notas Tecnicas

- **Padrao reutilizado:** `kiosk-middleware.ts` e `kiosk_tokens` — mesmo padrao de autenticacao por token + PIN
- **PIN hash:** bcrypt com salt rounds = 10
- **Session cookie:** `faction_session` (separado do `kiosk_session`)
- **Fluxo:** Admin gera link `liserie.lision.app/portal?token=<uuid>` → faccao abre → tela pede PIN → POST /api/faction/auth/login → cookie criado
- **Rate limiting:** Usar mesmo padrao de `/api/auth/pin` (Item 3 v2.1)
- **Source:** `docs/architecture/FACTION-PORTAL-ARCHITECTURE.md` secoes 2, 6
