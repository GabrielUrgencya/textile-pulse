## Descricao

Como gerente de qualidade, preciso ver a taxa de perda (allowance) detalhada por tipo de defeito, por responsavel e por faccao, com alerta automatico quando o threshold e excedido, para que eu identifique a origem dos problemas e aja preventivamente.

**Gap:** Taxa de defeito existe mas sem breakdown por motivo ou responsavel. Impossivel saber se o problema e costura, tecido, ou de qual operador/faccao.

**Solucao:** Novo endpoint GET `/api/quality/allowance` com breakdowns + componente AllowanceBreakdown + alerta no dashboard.

## Criterios de Aceitacao

- [ ] **AC1:** Given GET `/api/quality/allowance`, When chamado com periodo, Then retorna breakdown por tipo de defeito (% por tipo)
- [ ] **AC2:** Given breakdown por responsavel, When calculado, Then usa PENULTIMO scanner (nao ultimo) como responsavel real
- [ ] **AC3:** Given breakdown por faccao, When calculado, Then agrupa defeitos por faction_id
- [ ] **AC4:** Given taxa > 80% do threshold, When dashboard carrega, Then AllowanceAlert aparece como warning (amber)
- [ ] **AC5:** Given taxa > 100% do threshold, When dashboard carrega, Then AllowanceAlert aparece como destructive (red)
- [ ] **AC6:** Given taxa < 80% do threshold, When dashboard carrega, Then AllowanceAlert NAO aparece
- [ ] **AC7:** Given pagina `/quality`, When carrega, Then AllowanceBreakdown mostra DonutChart + BarChart
- [ ] **AC8:** `npm run typecheck` e `npm run lint` passam sem erros

## Notas Tecnicas

- **FALHA CORRIGIDA (Arq 12.1 #4):** Responsavel real = PENULTIMO scanner (quem operou ANTES da conferencia detectar), nao o ultimo.
- **REGRA 4 (Arq 12.2):** Tenant isolation em toda query
- **REGRA 7 (Arq 12.2):** Componentes em `src/components/quality/` e `src/components/dashboard/`
- **REGRA 8 (Arq 12.2):** Lib em `src/lib/allowance.ts`
- **UX (Arq 11.5):** AllowanceBreakdown = grid 2 colunas (DonutChart + BarChart horizontal). AllowanceAlert = Alert banner, warning (80-100%), destructive (>100%). Link "Ver detalhes" → `/quality`.
- **Performance (Arq 10):** Query com GROUP BY para 20k pecas/mes = <200ms
- **Config:** `settings.allowance_target = 0.002` (0.2%)

### Query de responsavel corrigida:
```sql
SELECT se.user_id as responsible_user
FROM scan_events se
WHERE se.lot_id = {lot_id}
  AND se.stage_id = {previous_stage_id}
  AND se.event_type = 'STAGE_IN'
ORDER BY se.scanned_at DESC LIMIT 1
```
