## Descricao

Como gerente do LISION, preciso que o dashboard use metas dinamicas configuradas em Settings (em vez de valores hardcoded), tenha um sino de notificacoes com alertas em tempo real (lotes parados, defeitos, remessas), e um activity feed humanizado em portugues, para ter visibilidade real da producao sem depender de configuracao manual e sem precisar navegar entre paginas para saber o que esta acontecendo.

**Contexto:** O dashboard ja existe e funciona com dados reais. Mas: (1) metas sao hardcoded no frontend, (2) nao ha notificacoes, (3) o activity feed mostra strings brutas de eventos. A Story 3.10 cria a API de targets — esta story consome esses dados. As APIs de notificacao devem ser criadas aqui (2 endpoints novos).

## Criterios de Aceitacao

- [x] **AC1 — Metas Dinamicas:** KPIs de meta no dashboard DEVEM ler de `GET /api/settings/targets` (criada na Story 3.10). O hook `useDashboardData` inclui fetch de targets como parte do carregamento. Barra de progresso: `pecas_bipadas / meta_diaria * 100`. Projecao de fim de turno: `(pecas_bipadas / horas_trabalhadas) * horas_restantes`. Visual: progresso abaixo de 80% da projecao = barra `warning` color, acima = `success` color. Se targets nao configurados, usa defaults (1000 pecas, 85% produtividade, 3% defeitos, 07:00-17:00).
- [x] **AC2 — Notification Bell (Header):** Icone de sino (Bell do Lucide) no header do layout (AppSidebar ou top bar). Badge numerico com contagem de notificacoes nao lidas. onClick abre Popover (320px largura, max-height 400px, scrollable). Header do Popover: "Notificacoes" + link "Marcar todas como lidas". Lista agrupada com dot colorido por severidade: destructive (lote parado >2h), warning (defeito registrado, faccao contestou), success (remessa recebida). Cada item: dot + mensagem + timestamp relativo ("ha 3 min", "ha 1h"). Footer: "Ver todas" (link inativo, futuro).
- [x] **AC3 — APIs de Notificacao:** (a) `GET /api/notifications?unread=true` retorna notificacoes do usuario/tenant, ordenadas por data desc. Campos: id, type, message, severity, isRead, createdAt. Limite: 50 mais recentes. (b) `PATCH /api/notifications/read` aceita `{ ids: string[] }` ou `{ all: true }` para marcar como lidas. Ambas usam `withAuth()`.
- [x] **AC4 — Polling de Notificacoes:** O Popover faz poll a cada 60 segundos (`setInterval` com cleanup). Badge atualiza automaticamente. Nao usar WebSocket (overkill para MVP).
- [x] **AC5 — Activity Feed Humanizado:** O feed de atividade existente no dashboard deve mapear eventos para frases em portugues: `STAGE_IN` → "{operador} bipou lote {barcode} em {etapa}", `DEFECT_REPORTED` → "{operador} reportou defeito em {barcode}", `REWORK_RESOLVED` → "{operador} resolveu retrabalho de {barcode}", `ORDER_CREATED` → "Nova OP {op_number} criada por {usuario}". Timestamps relativos: ate 24h usa "ha X min/h", apos 24h usa data absoluta (DD/MM HH:mm). API existente `GET /api/dashboard/activity` deve ser enhanceada para incluir nomes resolvidos (nao apenas IDs).
- [x] **AC6 — API Activity Enhancement:** `GET /api/dashboard/activity` deve retornar eventos com nomes resolvidos (profile.name para operador, stage.name para etapa, lot.barcode). Se ja retorna IDs, adicionar JOINs. Se ja retorna nomes, apenas formatar no frontend.
- [x] **AC7 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

const hoursRemaining = (shiftEnd - now) / (1000 * 60 * 60);
const rate = piecesScanned / hoursWorked;
const projected = piecesScanned + (rate * hoursRemaining);
const projectedPercent = (projected / dailyTarget) * 100;

### Possivel Schema de Notifications

```sql
-- Se tabela nao existir, criar migration:
CREATE TABLE notifications (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES tenants(id),
  user_id UUID REFERENCES profiles(id),  -- NULL = broadcast para tenant
  type TEXT NOT NULL,                      -- 'STALE_LOT', 'DEFECT', 'SHIPMENT', etc
  message TEXT NOT NULL,
  severity TEXT DEFAULT 'info',            -- 'info', 'warning', 'destructive', 'success'
  is_read BOOLEAN DEFAULT false,
  metadata JSONB,
  created_at TIMESTAMPTZ DEFAULT now()
);
-- RLS: tenant_id = auth_tenant_id() AND (user_id IS NULL OR user_id = auth.uid())
```
