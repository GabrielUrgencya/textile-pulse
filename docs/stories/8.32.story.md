## Descrição

Hoje há **1 plano por dia** visível a todos. A Karen precisa **atrelar planos a membros**: um plano para a Andiara, outro para a Costura, etc. — ou manter **geral**. A fundação de dados já permite **vários planos por dia**, cada um com `name` (rótulo opcional) e `is_general`; quando restrito, os membros ficam em `daily_plan_members`.

**Regra de visibilidade (decisão de produto):** se a pessoa logada tem ≥1 plano **atrelado a ela** hoje → vê **só esses**; senão → vê os planos **gerais**. (Específico tem prioridade.)

## Critérios de Aceitação

### A — API (por plano)
- [x] **AC1:** **Given** `GET /api/production/daily-plan?date=YYYY-MM-DD&scope=all` com `settings:manage`, **When** chamado, **Then** retorna **todos os planos** da data, cada um com `name`, `is_general`, `members` (ids/nomes) e `items` + meta calculada. (modo EDITOR)

- [x] **AC3:** **Given** `POST/PUT` com `{ id?, date, name?, is_general, member_ids[], items[], target_override?, notes? }` e `settings:manage`, **When** salvo, **Then** cria (sem id) ou edita (com id) **aquele plano**, com **replace** transacional de itens e de membros; se `is_general=true`, os membros são limpos.
- [x] **AC4:** **Given** `DELETE /api/production/daily-plan?id=...` com `settings:manage`, **When** chamado, **Then** remove o plano (cascade de itens e membros).
- [x] **AC5:** **Given** usuário **sem** `settings:manage`, **When** tenta POST/PUT/DELETE, **Then** recebe `403` (GET continua liberado).

## Notas Técnicas
- **Resolução de prioridade (AC2):** buscar planos do dia; separar restritos onde o usuário é membro; se houver, retornar esses; senão, retornar `is_general=true`.
- **Replace de membros:** ao salvar, apagar `daily_plan_members` do plano e reinserir os `member_ids` (quando `is_general=false`). Se `is_general=true`, garantir zero membros.
- **POST/PUT por plano:** a 8.27 fazia upsert por data; agora a identidade é o `id` do plano. Migrar o handler para operar por plano (criar quando sem id).
- **Membros:** `/api/team/members` já existe; usar id + full_name.
- **Permissão/seguro:** escrita `settings:manage`; RLS já criada (cadeia plan→tenant).
