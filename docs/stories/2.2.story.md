## Descrição

Como operador no chão de fábrica, preciso bipar o código de barras do lote com o leitor USB (Tomate) para registrar a passagem dele em cada etapa da produção, com feedback imediato visual e sonoro.

## Critérios de Aceitação

- [ ] **AC1:** Tela de bipagem (`/scan`) com campo de input auto-focus que recebe leitura do scanner USB (simula teclado HID). Input deve ter re-focus automático após cada bipagem (nunca perder foco)
- [ ] **AC2:** Ao bipar, sistema chama `POST /api/scan` com `{ barcode, stage_id, device_info }` e registra evento na tabela `scan_events`
- [ ] **AC3:** Feedback visual imediato baseado na resposta da API:
  - `200` → verde (sucesso) + dados do evento
  - `409` → amarelo (lote já bipado nesta etapa)
  - `404` → vermelho (lote não encontrado)
  - `400` → vermelho (formato de barcode inválido)
- [ ] **AC4:** Feedback sonoro: beep sucesso (tom agudo curto) vs beep erro (tom grave duplo) via Web Audio API (oscilador — sem arquivos externos)
- [ ] **AC5:** Seletor de etapa carregado dinamicamente da tabela `stages` via API (`GET /api/stages` ou query direta). Etapas reais do sistema: `CORTE → AVIAMENTOS → PRODUCAO → TRAVETE → LIMPEZA → CONFERENCIA → EMBALAGEM → ESTOQUE`
- [ ] **AC6:** Tela funciona em modo fullscreen para quiosque (botão toggle fullscreen via `document.documentElement.requestFullscreen()`)
- [ ] **AC7:** Latência máxima de 500ms entre bipagem e feedback visual/sonoro (debounce de 300ms para evitar dupla-bipagem acidental)

## Riscos

| Risco | Impacto | Mitigação |
|-------|---------|-----------|
| Scanner USB não dispara evento Enter | Bipagem não funciona | Fallback: botão manual "Confirmar" + listener `onKeyDown` genérico |
| Web Audio API bloqueada pelo browser | Sem feedback sonoro | Primeiro click do usuário desbloqueia AudioContext (user gesture requirement) |
| Latência da API > 500ms | UX degradada | Loading state otimista + spinner mínimo |
| Operador seleciona etapa errada | Scan fora de ordem | API já retorna `warning: "out of expected stage order"` — exibir alerta visual |

### API Backend Existente — POST /api/scan

**Arquivo:** `src/app/api/scan/route.ts` (Story 5.4 — DONE, não modificar)

**Payload:**
```json
{
  "barcode": "OP-20260309-001-L001",
  "stage_id": "uuid-da-etapa",
  "device_info": "mesa-1"
}
```

**Respostas:**
| Status | Significado | Body |
|--------|-------------|------|
| `200` | Sucesso | `{ scan_event, lot_status, warning? }` |
| `400` | Barcode inválido | `{ error: "Invalid barcode format..." }` |
| `404` | Lote ou etapa não encontrada | `{ error: "Lot not found" }` ou `{ error: "Stage not found" }` |
| `409` | Duplicata (lote já bipado nesta etapa) | `{ error: "Lot already scanned at stage X", scan_event_id }` |
| `500` | Erro interno | `{ error, details }` |

**Validação de barcode:** Regex `^OP-[0-9]{8}-[0-9]{3}-L[0-9]{3}$`

**Detecção de fora-de-ordem:** API retorna `warning` se scan é em etapa anterior à atual do lote — exibir como alerta mas não bloquear.

### Scanner USB HID

- Scanner USB HID envia caracteres como se fosse teclado, terminando com `Enter`
- Tratar como input de texto com submit no `keydown` do Enter (`e.key === "Enter"`)
- Input deve ter `autoFocus` e re-focus automático após cada bipagem
- Debounce de 300ms para evitar dupla-bipagem acidental (scanner pode enviar Enter duplicado)

### Web Audio API — Feedback Sonoro

```typescript
// Padrão para gerar beeps sem dependências externas
const audioCtx = new (window.AudioContext || window.webkitAudioContext)();

function beep(frequency: number, duration: number, type: OscillatorType = "sine") {
  const oscillator = audioCtx.createOscillator();
  const gainNode = audioCtx.createGain();
  oscillator.connect(gainNode);
  gainNode.connect(audioCtx.destination);
  oscillator.frequency.value = frequency;
  oscillator.type = type;
  gainNode.gain.value = 0.3;
  oscillator.start();
  oscillator.stop(audioCtx.currentTime + duration / 1000);
}

// Sucesso: tom agudo curto
beep(880, 150);

// Erro: tom grave duplo
beep(220, 200); setTimeout(() => beep(220, 200), 250);
```

**Importante:** `AudioContext` precisa de user gesture para iniciar. Criar o contexto no primeiro clique/interação do usuário.
