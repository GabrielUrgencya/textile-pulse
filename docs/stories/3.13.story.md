## Descricao

Como gerente do LISION, preciso de um modulo completo de gestao interna de faccoes — CRUD de faccoes, pagina de detalhe rica (score, remessas, defeitos, financeiro), criacao de novas remessas (selecao de lotes) e recebimento de devolucoes — para ter controle total sobre a producao terceirizada.

**Contexto:** A Story 3.8 criou uma versao inicial readonly (listagem + detalhes basicos). Esta story SUBSTITUI a 3.8 e expande para CRUD completo + funcionalidades de remessa. O schema ja tem `Faction`, `FactionShipment`, `FactionToken`, `FactionInvitation`. O portal EXTERNO das faccoes ja existe (`/api/faction/*` com 14 endpoints) e NAO DEVE SER TOCADO. Esta story cria a visao INTERNA do gestor. A UX define list→detail com paginas separadas (detalhe e rico demais para Sheet).

## Criterios de Aceitacao

- [x] **AC1 — Listagem:** Pagina `/factions` com PageHeader (eyebrow="Terceirizados", title="Faccoes"), botao "Nova Faccao" (abre Dialog). KPI Row: 4 MetricBox (Total Faccoes ativas, Remessas em Andamento, Taxa Media de Defeito %, Valor Total Pendente R$). DataTable com colunas: Nome, Tipo, Remessas Ativas, Rating (5 estrelas), Status (StatusBadge), Acoes. Linha clicavel → navega para `/factions/[id]`.
- [x] **AC2 — Criar faccao:** Dialog (modal centered, 520px). Campos: Nome*, Tipo* (Costura/Acabamento/Outro — dropdown), Nome Contato*, Telefone*, Endereco, Preco por peca (R$ — decimal input), Prazo medio (dias — numerico). Botao "Criar Faccao". API: `POST /api/factions`. Toast sucesso + recarrega lista.
- [x] **AC3 — Editar faccao:** Mesma Dialog com dados preenchidos. Botao "Salvar". API: `PATCH /api/factions/[id]`. Acessivel via botao "Editar" na listagem ou na pagina de detalhe.
- [x] **AC4 — Desativar faccao:** ConfirmDialog variant destructive. Titulo: "Desativar {nome}?". Consequencias: "Remessas ativas serao mantidas, mas novos envios nao serao possiveis." API: `PATCH /api/factions/[id]` com `{ isActive: false }`.
- [x] **AC5 — Pagina de Detalhe:** Rota `/factions/[id]`. PageHeader com nome da faccao + botoes "Editar", "Nova Remessa", "Desativar". Layout:
  - FactionScoreCard: Rating 1-5 estrelas (preenchimento parcial), + 3 SubMetrics (Pontualidade %, Qualidade %, Volume total pecas)
  - Informacoes de Contato (LisionCard): Nome, Tipo, Telefone, Endereco, Preco/peca
  - Remessas (tabs: Ativas | Historico): DataTable com Data envio, Lotes, Pecas, Prazo, Status (ENVIADA/RECEBIDA/DEVOLVIDA/ATRASADA), Acoes. Acao "Receber Devolucao" visivel em remessas ENVIADA.
  - Historico de Defeitos: DataTable com Data, Tipo, Severidade, Qtd, Status Contestacao
  - Resumo Financeiro: Valor bruto, deducoes, valor liquido do periodo atual. Chart simples: valores ultimos 6 meses (Recharts BarChart).
- [x] **AC6 — Criar Remessa (ShipmentCreate):** Dialog (640px) ou sub-pagina. Fluxo: (1) Selecionar lotes disponiveis via tabela com checkboxes (filtro por OP, mostra qtd pecas), (2) Definir prazo de devolucao (date picker), (3) Informar motorista (opcional, texto livre), (4) Tela de confirmacao com resumo (lotes selecionados, total pecas, prazo). Botao "Enviar Remessa". API: `POST /api/shipments` cria FactionShipment + atualiza status dos lotes selecionados.
- [x] **AC7 — Receber Devolucao (ShipmentReceive):** Dialog simples. Campos: Quantidade devolvida (numerico), Observacoes (textarea). Se quantidade < enviada: alerta visual de diferenca ("Atencao: {X} pecas a menos que o enviado"). Botao "Confirmar Recebimento". API: `PATCH /api/shipments/[id]/receive` atualiza shipment + retorna lotes ao fluxo produtivo.
- [x] **AC8 — APIs Factions:** (a) `GET /api/factions` com filtros (active, search) + KPIs agregados. (b) `POST /api/factions` cria nova faccao. (c) `GET /api/factions/[id]` com detalhes completos + shipments + defects + financial. (d) `PATCH /api/factions/[id]` edita faccao. (e) `GET /api/factions/[id]/shipments?status=` lista remessas com filtro. (f) `POST /api/shipments` cria remessa com lotes. (g) `PATCH /api/shipments/[id]/receive` recebe devolucao. (h) `GET /api/production/lots?available=true` lista lotes disponiveis para remessa. Todas requerem `factions:manage` via `withAuth()`.
- [x] **AC9 — Mobile:** Listagem: cards empilhados com nome, tipo, rating, status. Detalhe: secoes empilhadas, charts full-width. Dialog ShipmentCreate: full-screen no mobile.
- [x] **AC10 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

## Escopo

**IN:**
- CRUD completo de faccoes (criar, editar, desativar, listar, detalhar)
- Pagina de detalhe rica com score, remessas, defeitos, financeiro
- Criacao de remessas com selecao de lotes
- Recebimento de devolucoes
- 8 APIs (factions CRUD, shipments, lots available)
- FactionScoreCard component

**OUT:**
- Portal externo das faccoes (ja existe, NAO TOCAR em `/api/faction/*`)
- Convites para faccoes (invitation flow)
- Gestao de tokens de faccao (em Settings — Story 3.10)
- Relatorios financeiros detalhados/exportaveis
- Notificacoes push para faccoes sobre novas remessas
- Contestacao de defeitos pelo lado interno (ja existe no portal)

## Riscos

| Risco | Impacto | Mitigacao |
|-------|---------|-----------|
| Conflito com APIs do portal externo (`/api/faction/*`) | Quebra do portal | Rotas internas em `/api/factions/` (plural), portal em `/api/faction/` (singular). NUNCA modificar `/api/faction/*` |
| Selecao de lotes para remessa: query pode ser complexa | Performance | Limitar a lotes de OPs ativas com status adequado. Paginacao na selecao |
| Calculo de financeiro pode nao ter dados suficientes | Tela vazia | EmptyState com "Sem dados financeiros no periodo" + explicacao |

```prisma
model Faction {
  id              String   @id @default(uuid()) @db.Uuid
  tenantId        String   @map("tenant_id") @db.Uuid
  name            String
  type            String   // COSTURA, ACABAMENTO, OUTRO
  contactName     String?  @map("contact_name")
  contactPhone    String?  @map("contact_phone")
  address         String?
  pricePerPiece   Decimal? @map("price_per_piece")
  avgDeliveryDays Int      @default(7) @map("avg_delivery_days")
  rating          Decimal  @default(5.0)
  isActive        Boolean  @default(true) @map("is_active")
  shipments       FactionShipment[]
}

model FactionShipment {
  id              String   @id @default(uuid()) @db.Uuid
  factionId       String   @map("faction_id") @db.Uuid
  tenantId        String   @map("tenant_id") @db.Uuid
  status          String   @default("PENDING") // PENDING, SENT, RECEIVED, RETURNED, LATE
  totalQuantity   Int      @map("total_quantity")
  returnedQuantity Int?    @map("returned_quantity")
  sentAt          DateTime @map("sent_at")
  expectedReturn  DateTime @map("expected_return")
  receivedAt      DateTime? @map("received_at")
  notes           String?
}
```
