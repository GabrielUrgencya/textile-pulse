## Story

**Como** administrador do LISION Vendas,
**quero** controlar quais áreas do Vendas cada cargo e cada usuário enxerga,
**para que** eu possa ter administradores limitados (ex.: alguém que só lança vendas, sem acesso a Metas/Configurações), no padrão do controle de permissões do Lision.

## Contexto

Hoje o `SalesAdminRoute` é tudo-ou-nada: qualquer ADMIN do Vendas vê todas as áreas. A navegação (`SalesSidebar`) mostra todos os itens admin. Não há como restringir áreas por pessoa. O usuário quer esse controle no módulo de Configurações, por cargo E por usuário (o "por usuário" não existe no Lision).

## Áreas (chaves canônicas)
`dashboard, sales, team, payment-methods, goals, periods, calendar, closing, tv-access, config`
(Painel TV e Coletivo ficam sempre visíveis — não entram na matriz.)

## Critérios de Aceite

1. **Modelo de dados.** Tabelas `sales_area_permissions` (tenant, role, area, allowed) e `sales_user_area_permissions` (tenant, profile_id, area, allowed), com RLS tenant-scoped e escrita restrita a admin do Vendas.
2. **Efetivo.** Área visível = default por cargo (ADMIN = todas) ⊕ override por cargo ⊕ override por usuário (usuário vence). RPC `sales_my_areas_v1()` retorna as áreas efetivas do chamador.
3. **Gating de navegação.** `SalesSidebar` mostra só os itens admin cujas áreas o usuário tem.
4. **Gating de rota.** `SalesAdminRoute` bloqueia (forbidden) a página cuja área não é permitida ao usuário, mesmo digitando a URL.
5. **Editor.** Nova seção "Permissões" na config do Vendas: matriz cargo × área (toggles) + seção de overrides por usuário (buscar consultora/admin → togglar áreas). UI no padrão do `PermissionsEditor` do Lision.
6. **Anti-lockout.** Não é possível remover a área `config` do próprio admin que está editando (nem zerar `config` de todos os admins) — bloqueio com mensagem clara.
7. **Segurança.** RPCs admin-only (guarda `sales_is_admin`), REVOKE de anon, escopo por tenant.

## Escopo
**IN:** tabelas + RLS; RPCs (matriz, gravar, my-areas); gating em `SalesSidebar` + `SalesAdminRoute`; UI de Permissões na config. **OUT:** áreas do app da consultora (só admin nesta story); permissões de produção (Lision principal).

## Dev Notes
- Áreas ↔ rotas: mapear cada `ADMIN_ITEMS` de `SalesSidebar.tsx` a uma chave de área; `SalesAdminRoute` recebe/deriva a área pela `redirectPath`.
- `sales_my_areas_v1()` chamada uma vez no `SalesShell`/layout e passada à sidebar (ou fetch client no sidebar). Cachear por request.
- Defaults por cargo no código (ADMIN = todas as áreas admin). Overrides só quando presentes no banco.
- Editor: reutilizar padrão visual do `PermissionsEditor` (matriz com toggles + grupos), adaptado ao tema Vendas. Endpoints novos em `/api/vendas/admin/area-permissions` (GET matriz, PUT overrides) + `/api/vendas/admin/my-areas` (ou resolver server-side no layout).
- Migrations idempotentes + rollback; aplicar com probe→aplicar→verificar e OK do usuário.
