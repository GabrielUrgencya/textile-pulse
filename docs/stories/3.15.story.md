## Descricao

Como dona Terezinha (operadora de faccao), preciso que o portal das faccoes tenha navegacao por bottom tab bar (como WhatsApp), detalhes completos das remessas com timeline visual, e funcione como app instalavel no celular (PWA), para conseguir usar o sistema no meu Samsung Galaxy A14 com facilidade, sem me perder em menus complicados.

**Contexto:** O portal externo das faccoes ja existe em `/portal` com 14 APIs em `/api/faction/*`. A navegacao atual usa sidebar (inadequada para mobile). Dona Terezinha (persona de faccao) tem Samsung A14, tela 6.6", dados moveis limitados, letramento digital basico. A UX define bottom tab bar com 5 tabs, textos grandes, cores semanticas exageradas, sem tabelas, tudo em cards. PWA manifest permite instalar como app no celular.

## Criterios de Aceitacao

- [x] **AC1 — Bottom Tab Bar:** Barra fixa inferior (60px height, bg-surface) com 5 tabs icone+label: Inicio (/portal/dashboard), Remessas (/portal/shipments), Defeitos (/portal/defects), Financeiro (/portal/financial), Avisos (/portal/notifications + badge unread). Tab ativo: cor primary, icone filled. Tab inativo: muted. Touch target minimo 44px. Renderiza APENAS no portal (nao no app principal). A barra substitui qualquer sidebar/hamburger existente no portal.
- [x] **AC2 — Regras UX Portal:** (a) Uma acao principal por tela — botao CTA unico, grande (48px height, full-width). (b) Body text minimo 16px, titulos 20px+, labels 14px. (c) Cores semanticas exageradas: verde = bom, vermelho = atencao, amarelo = prazo. (d) SEM tabelas — tudo em cards empilhados. (e) Target de peso por pagina: < 200KB. (f) Feedback tatil: `navigator.vibrate(50)` em acoes de confirmacao (com fallback silencioso se API nao disponivel).
- [x] **AC3 — Dashboard Portal:** Tela de inicio com: "Ola, {nome}" (nome da faccao, 20px), Card principal "Pecas com voce: {N}" (numero 36px font-display), Card "Voce vai receber: R$ {X}" (32px, text-success) com data de pagamento, Mini-cards: "Devolucoes" (contagem) + "Proximo prazo" (data), Banner condicional "Nova remessa recebida!" com CTA "Confirmar Recebimento →" se houver remessa nao confirmada.
- [x] **AC4 — Shipment Detail (Completar):** Pagina de detalhe de remessa com: Card por lote (numero, qtd pecas, OP de origem), Timeline vertical (Enviado → Recebido → Devolvido) com status badges por etapa, Botao "Confirmar Recebimento" (verde, full-width, 48px) se status = SENT, Botao "Informar Atraso" (warning, outline, full-width) se perto do prazo.
- [x] **AC5 — PWA Manifest:** Arquivo `public/manifest.json` com: name "LISION Faccoes", short_name "Faccoes", start_url "/portal", display "standalone", theme_color (background do design system), icons (192x192 e 512x512). Meta tags no `<head>` do layout portal: `<link rel="manifest">`, `<meta name="theme-color">`, `<meta name="apple-mobile-web-app-capable">`. Service worker MINIMO: apenas cache de assets estaticos (nao offline-first completo).
- [x] **AC6 — Vocabulario Simplificado:** Usar mapeamento de termos do PERSONAS-AND-JOURNEYS.md Secao 6.4: "Shipment" → "Remessa", "Defect" → "Defeito/Problema", "Financial" → "Pagamentos", "Notification" → "Avisos", "Dashboard" → "Inicio", "Confirm Receipt" → "Confirmar Recebimento", "Contest" → "Reclamar". Todos os textos do portal em portugues coloquial, sem termos tecnicos.
- [x] **AC7 — Build e typecheck passam:** `tsc --noEmit` + `next build` sem erros.

## Riscos

| Risco | Impacto | Mitigacao |
|-------|---------|-----------|
| PWA manifest pode conflitar com o app principal | Confusao | Manifest APENAS no layout do portal, nao no layout global |
| navigator.vibrate() nao disponivel em todos os browsers | UX degradada | Usar com try/catch ou feature detection. Fallback: nada acontece |
| Bottom tab bar pode colidir com barra de navegacao do Android | Sobreposicao | Usar `env(safe-area-inset-bottom)` para respeitar area segura do dispositivo |
| Layout do portal atual pode ser muito diferente | Refatoracao grande | Focar no tab bar + dashboard. Ajustes nas demais paginas sao incrementais |
